# Code style, diagnostics, and lint gates

## Diagnostics and debug output

- Use the named spdlog categories in `<gleditor/logging.hpp>` for new diagnostic messages. Prefer a
  permanent `GLEDITOR_LOG_DEBUG` or `GLEDITOR_LOG_TRACE` call gated by `SPDLOG_LEVEL` over temporary
  `std::cout`, `std::cerr`, or `printf`. Name the subsystem in the category (for example,
  `text.layout`, `render.scene`, `xanadu.edit`, `xuzz.links`).
- Keep command results, REPL output, benchmark markers, and machine-readable protocol lines on their
  existing stdout streams. Never log document text, credentials, or key material in routine
  diagnostics.
- The macro checks the category level before evaluating formatting arguments; use that guard for
  expensive diagnostics in render and edit paths. See
  [`design/logging-migration.md`](../../../design/logging-migration.md) for the remaining conversion
  plan.

## C++23 and C++26 conventions

- `.clang-format` (LLVM-based, `IndentWidth: 2`, `ColumnLimit: 80`, aligned consecutive assignments)
  governs C++ **and `.glsl`**. `.editorconfig` mirrors formatter settings for editors (hint, not
  gate). Run `make format` before committing, or `clang-format-19 -i --style=file <file>`.
  **clang-format 19**: `.clang-format` requires 18+ (`AlignFunctionPointers`) and majors disagree on
  continuation indents, so `make format`/`format-check` prefer `clang-format-19` and refuse anything
  older by name.
- CI (`.github/workflows/c-cpp.yml`, job `format`) runs `make format-check` and `make lint` with no
  build dependencies installed (via `NO_SDL_GOALS` in the Makefile).
- `.clangd`/`.clang-tidy` enable `modernize-*`, `bugprone-*`, `cppcoreguidelines-*`,
  `performance-*`, `readability-*`, `portability-*`, `clang-analyzer-*` (minus `.clangd`
  exclusions). Fix warnings on lines you touch.
- Comments explain *why* a non-obvious choice was made (constraint, workaround, tradeoff), never
  what the code does.
- `compile_commands.json` is regenerated by `make`; do not hand-edit it.
- **No sentinels outside the wire and on-disk formats.** In an API, "no cell", "no index", and
  similar absences are `std::optional` or `std::expected`, never a reserved sentinel like `noCell`.
- **Setters chain.** Mutators with nothing else to return give back a pointer to the object (as
  `ArenaManifold`'s do); refusable mutators return `std::expected` of it.
- C++26 facilities (`function_ref` for non-stored callbacks, `optional<T&>` and optional-as-range,
  `inplace_vector` for design-bounded vectors, two-span `views::concat`, checked `span_at`) come
  from `<gleditor/cpp26*.hpp>` as `gleditor::cpp26::*` across library and apps. Never test
  `__cpp_lib_*` directly: `cpp26_select.hpp` chooses once so everything linked against `libgleditor`
  agrees. See [`design/cpp26-compatibility.md`](../../../design/cpp26-compatibility.md).

## Formatting and linting, by language

| Language                                    | Formatter                                      | Linter                                                       | CI gate                                         |
| ------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------- |
| C++ (`.cpp`/`.hpp`/`.h`)                    | clang-format                                   | clang-tidy (`make tidy`), scan-build                         | blocking; `make check` runs all gates           |
| GLSL (`.glsl`)                              | clang-format                                   | `glslangValidator` via `make shaders`                        | blocking (both)                                 |
| Shell (`.sh`, `PKGBUILD`)                   | shfmt `-i 2 -ci`                               | shellcheck                                                   | blocking                                        |
| YAML (workflows, dependabot)                | yamlfmt (`.yamlfmt`)                           | yamllint (`.yamllint`)                                       | blocking                                        |
| Markdown (all `*.md` outside `thirdparty/`) | mdformat `--wrap 100` + three required plugins | mdl `-i` (`.mdlrc`, `.mdl_style.rb`)                         | blocking                                        |
| Nix (`flake.nix`, `packaging/nix/`)         | nixfmt-rfc-style (the flake's `formatter`)     | nix-linter                                                   | blocking, job `nix` (needs Nix)                 |
| Ruby (`packaging/macos/gleditor.rb`)        | `brew style` (needs Homebrew; not in CI)       | `ruby -c`                                                    | non-blocking (`packaging.yml`, `macos`)         |
| RPM spec (`packaging/fedora/`)              | —                                              | rpmlint, inside the `fedora:latest` packaging container only | non-blocking until triaged                      |
| Debian (`debian/`)                          | —                                              | —                                                            | not covered (`debian/rules` is a `dh` Makefile) |

`tools/check-config-harmony.sh` keeps `.editorconfig`, `.clang-format`, `.yamlfmt`, `.yamllint`,
`.mdl_style.rb`, `.clangd`, and `.clang-tidy` aligned. `mdformat` requires `mdformat-gfm`,
`mdformat-dollarmath`, and `mdformat-frontmatter` (for `.claude/skills/*/SKILL.md` frontmatter, also
exposed via `.agents -> .claude`). See
[references/formatter-quirks.md](references/formatter-quirks.md) for plugin flags, Ruby `GEM_HOME`
for `mdl`, `MD013` math/code fence rules, and `yamlfmt` caveats.
