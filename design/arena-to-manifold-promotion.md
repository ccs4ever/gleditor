## 1. The Architectural Divide: Ephemeral Evaluation vs. Persistent History

In the Nelsonian hyperstructural model implemented across `gleditor`, `xudu`, and `zigzag`, every
permanent state mutation is recorded as an immutable, append-only operation within a
`SegmentedOpsSpool` (`CompactOpNode`), forming a cryptographically authenticated microversion DAG in
a `xanadu::Store`. A persistent [`zigzag::Manifold`](../apps/common/xanadu/zigzag/manifold.hpp) is
the materialized replay product of these operations.

However, interactive editing, query planning (VQL), array evaluation (VPL), and logic resolution
(Vlog/Prolog) generate vast amounts of speculative structure: intermediate variables, search tree
explorations, backtracking choice points, and scratch text concatenations. Persisting every
computational step directly into the microversion DAG would trigger catastrophic spool bloat and
violate the fundamental architectural boundary:

> **Invariant R8:** *Only a user-generated update persists. Navigation and intermediate computation
> never do.* An operation records that a person or committed transaction changed the structure.
> Where a cursor, query, or evaluator looks or speculates is not a change to the document and does
> not earn a name in hypertime.

To enforce this boundary cleanly without runtime tagging overhead or fragmented allocations, the
architecture establishes two distinct, non-interchangeable concrete C++ types:

```cpp
class Manifold;      // Ops-backed. Every mutation appends a CompactOpNode.
class ArenaManifold; // Dense vectors only. Zero ops. Dies with its owner.
```

An [`ArenaManifold`](../apps/common/xanadu/zigzag/arena_manifold.hpp) operates purely in contiguous
flat vectors (`CellSlot`, `DimLink`, `PrimediaSpan`). It supports $O(1)$ choice points via `mark()`,
reclamation via truncation in `release(Mark)`, and conditional trailing.

**Promotion** is the formal, controlled transition mechanism through which cells, text, and links
minted in an ephemeral `ArenaManifold` cross the boundary into a persistent `Store` and `Manifold`.

## 2. Invariants Enforced at the Promotion Boundary

Promotion is not an open bridge or a blind serialization dump; it is a validating transform that
enforces three foundational invariants:

### 2.1 The R8 Identity Barrier (`ephemeralBit`)

Every cell minted by an `ArenaManifold` carries `ephemeralBit`:

```cpp
static constexpr CellRef ephemeralBit = 0x80000000;
[[nodiscard]] static constexpr CellRef refOf(std::uint32_t dense) noexcept {
  return ephemeralBit | dense;
}
```

This is not a mere debugging tag; it is a structural guardrail. `Store::setLink()` and
`Manifold::applyStructure()` actively throw or refuse any operation naming an `ephemeralBit`
reference. An arena cell reference can **never** be placed directly into a persistent operation
node. Promotion must explicitly translate every ephemeral reference into a sequentially minted
persistent `CellRef`.

### 2.2 The R6 Scalar Duality

In an `ArenaManifold`, scalar cells (doubles, 64-bit integers, booleans) store raw bits in
`ValueBits` with zero text allocation. Rendering strings during speculative arithmetic is a needless
tax.

In a persistent `Manifold`, however, **Invariant R6** dictates that every scalar cell must possess
both its raw machine representation and a canonical ASCII string rendering spooled into the
permascroll. This ensures that text-based viewers, spanfilades, and transclusion engines can address
and render numeric cells without knowing numeric type schemas. Promotion is where this deferred
rendering is computed and spooled.

### 2.3 Scratch Scroll Address Realization (`scratchScroll`)

When an arena evaluates string operations or synthesizes text, the generated bytes cannot be spooled
to the author's real permascroll (`000.scroll`), because permascrolls are append-only global logs.
Spooling during uncommitted execution would pollute the author's public identity ledger with bytes
from failed branches.

The arena therefore buffers these ephemeral strings locally under a reserved address:

```cpp
inline constexpr ScrollId scratchScroll = breakMarkerScroll - 2;
```

Persistent stores refuse any span naming `scratchScroll`. Promotion is the exclusive point where
scratch text is spooled into the author's real permascroll, giving ephemeral bytes a permanent,
cryptographically authenticated address.

## 3. The Three Promotion Mechanisms

Depending on the operational context, cells transition from the arena to the persistent manifold
through three distinct mechanisms:

1. **Root-Reachable Graph Promotion (`zigzag::promote`)** — Focused query/resolution result adoption
   ("Promote the answer, not the search").
1. **Copy-on-Write (COW) Overlay Delta Promotion** — In-place non-destructive document augmentation.
1. **Whole-Manifold Program Export (`VPLCompiler::exportToStore`)** — Whole-program compilation and
   library serialization.

```
+---------------------------------------------------------------------------------------+
|                                    ArenaManifold                                      |
|                                                                                       |
|  [Root Cell] ---> [Reachable Answer Cells]         [Dead / Backtracked Search Tree]   |
|        |                  |                                        |                  |
|        |                  |                                        x (Pruned)         |
+--------+------------------+-----------------------------------------------------------+
         |                  |
         | (1. promote())   | (2. Overlay Delta)
         v                  v
+---------------------------------------------------------------------------------------+
|                             zigzag::promote() Pipeline                                |
|                                                                                       |
|  Phase 1: BFS Reachability Walk & PromotionBudget Check (<= maxOps)                   |
|  Phase 2: Cell & Span Realization (scratch -> Permascroll, R6 Scalar rendering)       |
|  Phase 3: Link Topology Translation (ephemeralBit stripped, known.advance())          |
+---------------------------------------------------------------------------------------+
                                     |
                                     v
+---------------------------------------------------------------------------------------+
|                                  xanadu::Store                                        |
|                          (Persistent Microversion DAG)                                |
+---------------------------------------------------------------------------------------+
```

## 4. Mechanism 1: Root-Reachable Graph Promotion (`zigzag::promote`)

The primary promotion API is defined in `arena_manifold.hpp` and implemented in
`arena_manifold.cpp`:

```cpp
[[nodiscard]] std::optional<Promoted>
promote(xanadu::Store &store, const xanadu::MicroversionId &parent,
        const ArenaManifold &from, CellRef root, PromotionBudget budget = {});
```

This implements the principle: **"Promote the answer, not the search."**

### Phase 1: Reachability Sweep & Transactional Budget Check

Promotion begins with a breadth-first search starting exclusively at `root`:

```cpp
std::vector<CellRef> order;
std::unordered_set<CellRef> seen;
order.push_back(root);
seen.insert(root);

for (std::size_t i = 0; i < order.size(); i++) {
  for (const auto &edge : from.dimensionsOf(order[i])) {
    for (const CellRef next : {edge.dim, edge.pos, edge.neg}) {
      if (noCell != next && from.contains(next) && seen.insert(next).second) {
        order.push_back(next);
      }
    }
  }
  if (order.size() > budget.maxOps) {
    return std::nullopt; // Budget exceeded: refuse immediately
  }
}
```

- **Dead Branch Elimination**: Any cell generated on a branch that backtracked, or any intermediate
  binding not linked to the answer graph, is unreachable from `root`. It is dropped automatically
  without bookkeeping overhead.
- **Transactional Refusal**: If the reachable subgraph exceeds `budget.maxOps` (default 65,536), the
  function returns `std::nullopt` before minting a single operation. The store remains completely
  unmodified.

### Phase 2: Cell Creation & Span Realization

For each reachable cell in discovery order, `promote()` creates a permanent cell in `store`:

```cpp
std::unordered_map<CellRef, CellRef> real;

for (const CellRef arena : order) {
  if (!isEphemeral(arena)) {
    // Overlaid base cell already exists; maps to itself.
    real.emplace(arena, arena);
    continue;
  }

  const auto spans = from.contentOf(arena);
  const auto kind  = from.valueKindOf(arena);
  xanadu::MicroversionId minted = out.version;

  if (ValueKind::Double == kind) {
    // R6 fulfillment: persists IEEE 754 bits and spools ASCII rendering
    minted = store.makeScalarCell(out.version, from.asDouble(arena).value_or(0.0));
  } else if (ValueKind::Int64 == kind) {
    minted = store.makeScalarCell(out.version, from.asInt64(arena).value_or(0));
  } else if (ValueKind::Bool == kind) {
    minted = store.makeScalarCell(out.version, from.asBool(arena).value_or(false));
  } else if (spans.empty()) {
    minted = store.makeCell(out.version, std::string_view{});
  } else if (scratchScroll == spans.front().scroll) {
    // Ephemeral scratch text is spooled to the author's permascroll
    minted = store.makeCell(out.version, from.scratchTextOf(spans.front()));
  } else {
    // Existing primedia span: transcluded without duplicating bytes
    minted = store.makeCell(out.version, spans.front());
  }

  out.version = minted;
  const CellRef realCell = store.cellRefOf(minted);
  real.emplace(arena, realCell);
  out.cells.push_back(realCell);

  // Additional spans in a multi-span run are appended as splices
  std::uint64_t at = spans.empty() ? 0 : spans.front().length;
  for (std::size_t i = 1; i < spans.size(); i++) {
    const auto &span = spans[i];
    if (scratchScroll == span.scroll) {
      out.version = store.spliceCell(out.version, realCell, at, 0,
                                     from.scratchTextOf(span));
    } else {
      out.version = store.spliceCellSpan(out.version, realCell, at, 0, span);
    }
    at += span.length;
  }
}
```

### Phase 3: Link Topology Translation & Incremental Advancement

Links require both endpoints to exist, so edge creation takes place in a second pass over the
reachable nodes. Only posward edges are processed, as the underlying `store.setLink` automatically
maintains bidirectional symmetry:

```cpp
auto known = store.rebuildManifold(out.version);

for (const CellRef arena : order) {
  for (const auto &edge : from.dimensionsOf(arena)) {
    if (noCell == edge.pos) continue;

    const auto dim = real.find(edge.dim);
    const auto to  = real.find(edge.pos);
    if (dim == real.end() || to == real.end()) continue;

    out.version = store.setLink(out.version, real.at(arena), dim->second,
                                false, to->second, &known);
    known.advance(store, out.version);
  }
}
```

- **Avoiding $O(N^2)$ Rebuilds**: `store.setLink()` requires a manifold to inspect each cell's
  `lastOp` chain. Rebuilding the manifold from scratch for every link in a large answer would result
  in quadratic overhead. Passing `&known` and calling `known.advance(store, out.version)` maintains
  an incrementally updated manifold in $O(1)$ per edge.

## 5. Mechanism 2: Copy-on-Write Overlay Delta Promotion

When speculative evaluation must run against an existing document (e.g. executing a Prolog query
against a knowledge base or performing an interactive VPL transformation on document text), the
`ArenaManifold` is constructed with a pointer to the base `Manifold`:

```cpp
ArenaManifold arena{&baseManifold};
```

### 5.1 Read Fall-Through and Shadowing

1. **Read Fall-Through**: Reading an unmutated cell incurs no copying. Traversal queries inspect
   `baseManifold` directly with zero allocations.
1. **Shadowing on Write**: When the arena mutates a cell belonging to the base document, it
   **shadows** it. The entire cell slot, its links, and content runs are copied into the arena's
   local vectors. Crucially, **the shadow retains the base cell's original `CellRef`** (without
   `ephemeralBit`).
1. **Displaced Occupant Shadowing**: If an edge mutation overwrites a link on a base cell, the
   far-end occupant is also shadowed, ensuring referential integrity within the arena.

### 5.2 Delta Promotion

When `promote()` is called on an overlaid arena:

- **Base cells map to themselves**: Since `isEphemeral(arena) == false`, the cell already possesses
  a permanent identity in the document. No new cell operation is minted
  (`real.emplace(arena, arena)`).
- **Only invented cells are minted**: Only cells minted directly in the arena (carrying
  `ephemeralBit`) trigger `makeCell` or `makeScalarCell`.
- **Topological Re-linking**: Any modified or newly attached edges between base cells and new cells
  are emitted as standard `SetLink` operations.

This provides seamless **delta promotion**: speculative work updates the document without
duplicating existing subgraphs or re-minting existing text.

## 6. Mechanism 3: Whole-Manifold Program Export (`VPLCompiler::exportToStore`)

In ahead-of-time compilation scenarios—such as compiling VPL source into a persistent standalone
store (`vplc -o <dir>`) or generating reusable Vortex bytecode libraries—the goal is not to extract
a single answer subgraph, but to serialize an entire compiled execution topology.

Implemented in [`VPLCompiler::exportToStore`](../apps/common/xanadu/vpl/compiler.cpp):

```cpp
MicroversionId VPLCompiler::exportToStore(Store &store, const MicroversionId &parent) const;
```

### Steps in Whole-Program Export:

1. **Dimension Reconciliation**: Iterates through all cells in the arena identifying dimension names
   (`d.*`). If the persistent store already possesses a dimension by that name, it maps to it;
   otherwise, it mints a new dimension via `store.makeDimension()`.
1. **Exhaustive Cell Translation**: Iterates across all active arena cells
   ($1 \le c \le \text{cellCount()}$), minting scalar cells via `makeScalarCell` and textual cells
   via `makeCell`, mapping each arena dense ID to its persistent `CellRef`.
1. **Hyperstructural Wiring**: Iterates through all arena link runs, creating persistent edges for:
   - The primary instruction stream (`+d.spin`).
   - Dual-wing parameter bindings (`+d.grab` for inputs, `-d.grab` for outputs).
   - Stepping sequences (`+d.step`).
   - Module entrypoints and symbol rosters (`+d.stdlib`, `+d.vars`, `+d.values`).

## 7. Comparative Summary of Promotion Modes

| Metric / Behavior       | Root-Reachable (`promote`)     | Overlay Delta (`promote`)    | Whole-Program (`exportToStore`)   |
| :---------------------- | :----------------------------- | :--------------------------- | :-------------------------------- |
| **Primary Use Case**    | Query / Vlog / VPL expressions | Interactive document editing | Compiler CLI (`vplc`), libraries  |
| **Selection Strategy**  | BFS walk from `root`           | BFS walk from `root`         | Linear sweep over all dense slots |
| **Unreachable Cells**   | Silently dropped (pruned)      | Silently dropped (pruned)    | Fully exported if allocated       |
| **Base Document Cells** | N/A (unbacked arena)           | Mapped to self; zero ops     | N/A (fresh store creation)        |
| **Scratch Buffer Text** | Spooled to permascroll         | Spooled to permascroll       | Spooled via string values         |
| **Scalar Cells (R6)**   | Bits + permascroll text        | Bits + permascroll text      | Bits + permascroll text           |
| **Safety Guard**        | Rejects `ephemeralBit`         | Rejects `ephemeralBit`       | Maps all slots via `cellMap`      |
| **Budget Enforcement**  | Yes (`PromotionBudget`)        | Yes (`PromotionBudget`)      | Unbounded (compiler-driven)       |
