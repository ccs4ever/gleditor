- **R1.5 (C++ intrusion in deliberation backpropagation)**: **RESOLVED**. Blind plan completion

  settlement runs entirely in pure Vortex bytecode generated by `compiler.cpp`: `rtSettle_` drains
  the Agent Settle Queue on `+d.epistemic` off `$agent` and updates source profile masters on
  `+d.trust` before yielding `Halt`, keeping all state transitions inside the verified actor turn

- **R1.6 (Unbounded memory growth on trust and clause ranks)**: **RESOLVED**. Section 2.4 specifies

- **R1.8 (Non-contextual formula mislabeled as LinUCB)**: **RESOLVED**. Section 3.4 cleanly delineates

## MINOR

### 1. (§8.1, lines 856–857) Explicit Reconciliation Phase Ordering: Source Profiles Before Belief Clauses

**Problem:** In §8.1 (Proposal P19.1), `reconciler.cpp:465–480` `fromDims` and live upgrade migration
logic are mandated to preserve source profiles on `+d.trust`. However, the document does not specify
the exact ordering of migration phases in `reconciler.cpp`.

In `apps/common/xanadu/vagent/reconciler.cpp:605–670`, belief clauses and their asserting sources along
`+d.source` are cloned via `cloneGraph(fromArena, toContext.arena, clause, termFrom, termInto)`. Under
Decision `U-C1` (§2.2), asserting source cells on `+d.source` are clone instances linking to clone
masters on `+d.trust` along `+d.clone`. If belief base reconciliation runs *before* source profile
reconciliation, source clone instances cloned into `toContext.arena` cannot link to their new clone
masters on `toAgent`'s `+d.trust` rank, or worse, their `+d.clone` links would point to obsolete cells
in `fromArena`.

**Fix:** In §8.1, explicitly specify that source profile reconciliation along `+d.trust` executes
**prior** to belief base reconciliation (Phase 4 in `reconciler.cpp`):

1. **Step 3b (Source Profile Migration)**: Walk `rankedFrom(fromAgent, fromDims.trust)`. For each source
   profile cell, clone its attribute subgraph along `valueFrom`/`valueInto` and link to `toAgent` along
   `toDims.trust`. Maintain a local mapping table `sourceMasterMap[fromMaster] = toMaster`.
2. **Step 4 (Belief Clause Migration)**: When cloning clauses along `+d.source`, re-link each cloned
   source instance on `+d.clone` to its corresponding newly migrated master in `sourceMasterMap`.

### 2. (§2.1, line 273 & §6.3, line 705) Explicit Documentation of Dual Role for `d.epistemic`

**Problem:** In §2.1 (line 273), `d.epistemic` is introduced as originating at individual predicate
descriptor cells on `+d.belief` to link per-predicate calibration overrides. In §6.3 (line 705) and §8.5
(line 914), `+d.epistemic` is also used off the agent root cell (`$agent`) to anchor the Agent Settle
Queue. While ZigZag dimensions are topological relations that can head distinct ranks off distinct
parent cell kinds, using the same dimension name for two structurally different subsystems can confuse
compiler and runtime maintainers inspecting the manifold.

**Fix:** Add a clarifying note in §2.1 and §6.3 documenting that `d.epistemic` has two well-defined,
disjoint roles differentiated by the originating cell type:
- Off a `PredicateDescriptor` cell on `+d.belief`: heads the predicate calibration override rank.
- Off the `$agent` root cell: heads the ephemeral Agent Settle Queue rank drained by `rtSettle_`.

## Architectural Assessment Summary

1. **Layer Separation**: The design strictly confines all additions to the `apps/common/xanadu/` engine
   layer (`vagent` compiler/reconciler and `vortex` VM/stdlib). Generic library code (`src/`,
   `include/gleditor/`) and graphical front-end layers (`apps/common/ui/`, `apps/xuzz/`) remain 100%
   unmodified, conforming to repository architectural layering rules.
2. **Vortex vs. C++ Division of Labor**: High-level dynamic weighting, Bayesian evidence combination,
   Gaussian fusion, clustering, and online SGD are entirely implemented in pure Vortex bytecode within
   `vortex_stdlib` (`std:epistemic`). C++ is reserved strictly for compiler AST/lowering, state
   reconciliation across P17 live upgrades, and three primitive hardware float instructions
   (`OpcodeKind::Exp`, `OpcodeKind::Ln`, `OpcodeKind::Sqrt`) justified by FPU performance and priced in
   Proposal P19.7.
3. **Hyperstructural Topology**: All epistemic metadata, Bayesian priors ($\alpha, \beta$), weights, and
   provenance relations reside on orthogonal ZigZag dimensions (`d.trust`, `d.epistemic`, `d.clone`,
   `d.vars`, `d.values`, `d.step`) in the ephemeral agent overlay (Rule V12). Hidden C++ side tables
   are zero.
4. **Mechanical Sympathy & Lifecycle Safety**: The design enforces strict resource bounds:
   `vagent.max_sources = 128` with LRU pruning, P18.3 key-tuple replacement preventing clause bloat,
   $m_{\text{eval}}$ inner mark scoping truncating scratch cells via `arena.release(m_{\text{eval}})`, and
   settle queue isolation guaranteeing verified refutations survive speculative plan failure.
