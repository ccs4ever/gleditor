## Proposal register

- **P3 (not applied; owner approval needed): off-thread Store save for capture commit.** Core file
  `store.hpp`/`store.cpp`. `Store::save()` reads the whole store the owner mutates, so it cannot
  move to a worker. Diff: a `Store::saveSnapshot()` that copies the in-memory tail (ops spool
  segments above the last saved count and `store.tables`) on the owner in O(new ops), and a
  `SnapshotWriter` the worker runs to write and fsync it; or an incremental
  `Store::saveSince(count)` appending sealed segments only. Cost: one core API, a crash-order test,
  roughly a week. Fallback (current): commit stays owner-blocking and the plan names it as the
  deviation from §14. With P3, `commit()` splits into an owner step (validate, publish) and a
  `CaptureDurable` worker adapter (sink sync, journal fsyncs, save) with an owner-side continuation,
  keeping the order Appended (after sync) -> publish -> save -> Committed.
- P1, P2: see disposition A. No other core-file change was made.

## Notes

- `capture.journal` is version 3; version 2 is refused by number. No fixtures under `tests/samples`
  hold one.
- A durable-origin capture's journal records are never retired; they are the only translations a
  restart can rebuild, and the journal bound refuses them explicitly.
