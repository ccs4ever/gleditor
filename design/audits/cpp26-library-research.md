# C++26 library research, 2026-10-26

Baseline: fetched `origin/main`, `126be39e8e4936133ade433ddcc4c0f40e2678ec`. This is a research and
adoption decision record. No dependencies or production APIs were changed. Upstream pages were
checked on 2026-10-26; their current status does not certify the older pins.

## Decision

Broaden the useful, tested subset already exposed before adding dependencies. No additional library
in this survey simultaneously demonstrated an urgent repository use, close C++26 API parity, and
unqualified production readiness across the supported toolchains. The strongest additional container
candidate is PLF hive, conditional on a real stable-address, unordered-churn workload. The strongest
functional additions need no dependency: C++23 ranges, optional/expected monadic operations, pure
local transformations, and the existing borrowed callable facade.

"Production ready" here requires evidence beyond implementing a paper: maintained source and tests,
a suitable license, documented compiler support, known ownership and exception behavior, and no
upstream warning ruling out production use. A mature related library is useful evidence, but does
not establish that its API or a new adapter is standard-conforming. Recommendations below are our
assessment, separate from upstream status statements.

## Current boundary

The selector is `include/gleditor/cpp26_select.hpp`. The facade offers five feature groups:

| Feature                        | Source and pin                                                  | Scope to preserve                                                                         |
| ------------------------------ | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `function_ref`                 | nontype_functional `57854ce32506ec526347637e8fcc226624466bbf`   | Synchronous borrowed callables; no retained callbacks or common constructor-tag API.      |
| Optional references and ranges | Beman optional `b239e587c3ecd9ae9a3bd01f6318d825241afefe`       | Borrow lifetime and mutation invalidation remain caller obligations.                      |
| `inplace_vector`               | Beman inplace_vector `c7fe76da307f0d6fda5023b2d2ebef7e3f7b18d1` | Restrict methods to verified common subset; preserve dynamic path for configurable sizes. |
| `views::concat`                | Native or local C++23 join adapter                              | Exactly two homogeneous const spans; only input range and reference semantics promised.   |
| `span_at`                      | Native or local checked free function                           | Throws on invalid access; parser refusal behavior must remain explicit.                   |

Native choices are per feature, not a consequence of the dialect flag. Installed builds freeze
choices in a generated config and install fallback headers. Do not place these types in persistent
formats. The separate [systems audit](cpp26-systems-auditor.md) records probes and coverage limits.

## What libraries cannot supply transparently

Language features such as reflection, pack indexing, contract semantics and compiler-supported
constant evaluation need compiler support. Similarly a library cannot add members to `std::span`,
`std::variant`, streams or standard associative containers. Free-function facades can offer a
selected contract, as `span_at` already does, but must be named and tested honestly.

Use [LLVM's official status table](https://libcxx.llvm.org/Status/Cxx26.html) to distinguish library
and compiler implementation work. Small changes such as member visit, stream native handles,
heterogeneous insertion and expanded constexpr support should be consumed natively when the
supported toolchains converge. Copying a standard-library header from GitHub is not a portable
polyfill strategy; it can depend on implementation internals and runtime ABI.

## Admission gate for a future dependency

1. Name the concrete consumer and benefit, including why the existing standard library and facade
   are insufficient. Confirm the feature is in C++26 rather than a later proposal.
1. Inspect the exact release/commit, license, supported platforms, upstream tests and unresolved
   correctness issues. Pin a Git submodule and license; never edit thirdparty headers.
1. Specify the common native/fallback contract, including constructors, qualifiers, exceptions,
   iterator categories, invalidation, constexpr and allocation behavior. Avoid promises the fallback
   cannot satisfy.
1. Add selection once in `cpp26_select.hpp`, install the frozen choice and required headers, and
   test downstream consumption. Audit ABI-bearing public uses separately.
1. Validate native, forced fallback and mixed installed-consumer scenarios. Measure performance on
   repository data if performance is the rationale. Recheck packaging platforms.

Effort estimates are planning judgments, not benchmarks or adoption commitments. Upstream speed
claims are not evidence of speedup in gleditor.
