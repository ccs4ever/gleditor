# 5.11 — Published vocabularies: dimension identity across documents

Implementation plan for §5.11 of [`structure-hyperop-vision.md`](../structure-hyperop-vision.md).
**Status:** ready after its dependencies, with one correction: quoting a vocabulary makes its terms
visible, but a term becomes a usable local dimension only when its foreign identity is filed as a
persistent placeholder (§4). **Depends on:** [§5.10](5.10-quoted-structure.md) phases 1–2 for
adoption and materialisation, [§5.5](5.05-extern-refs.md) for a durable reference to each term, and
[§5.7](5.07-arena-federation.md) for bound sets with provenance. **Provides:** the `SharedIdentity`
binding evidence consumed by §5.7 and §5.12 overlays.

The vision calls this “no operations of its own,” and that remains true: vocabulary publication,
adoption and use are all ordinary `MakeCell` and `SetLink` operations using mechanisms specified by
§5.5 and §5.10. What needs a plan is the identity rule. Two dimensions named `supports` are not the
same dimension merely because their content has the same bytes.

## 1. The correction: a quoted catalogue is not yet a dimension binding

§5.10 makes a published `d.dims` rank visible in an `ArenaManifold`. Its materialised cells are
ephemeral proxies, and R8 deliberately prevents an ops-backed `Store::setLink()` from naming one.
That is correct for reading, but it means this is not sufficient:

```text
quote Alice's d.dims → see [supports] [refutes] [qualifies]
```

To author a local `SetLink` on Alice's `supports`, the local store needs a persistent cell it can
put in `CompactOpNode::linkId`. The cell is §5.5's placeholder for Alice's term. R2 then does the
rest: **a placeholder is a cell, so it can be a dimension cell.** No foreign `CellRef` enters the
local spool and no new link encoding is needed.

The two acts stay separate because they mean different things:

| act   | persistent statement                                        | result at read time                         |
| ----- | ----------------------------------------------------------- | ------------------------------------------- |
| adopt | a §5.10 `rank` quotation of a vocabulary release            | the catalogue is visible and navigable      |
| use   | a §5.5 placeholder for one published term on local `d.dims` | local Structure operations may use the term |

Adoption need not file every term. A vocabulary may contain thousands of dimensions while one
document uses three; only those three earn local placeholders. This is the same sparse rule §5.2
uses for operation handles and §5.7 uses for foreign proxies.

## 2. Identity is the term's address, never its spelling

A published term is an ordinary dimension cell. Its durable identity is the `GlobalOpRef` of the
`MakeCell` that minted it. Its content is a human-readable label, not a key:

```text
Alice/vocab argumentation
  release ──d.dims──> [supports] ──> [refutes] ──> [qualifies]
```

Three consequences are rulings rather than implementation details:

- Two cells whose content is `supports` are **different dimensions** until both documents cite the
  same published term. String equality is a UI suggestion, never identity.
- Renaming or correcting a term with `SetValue` preserves its identity. Replacing its meaning mints
  a new term cell; the model cannot decide whether an edit was semantic, so publication tooling must
  make “revise label” and “mint successor” distinct actions.
- A local alias does not fork the dimension. It is a note or name attached to the placeholder; the
  placeholder still resolves to the same `GlobalOpRef`.

This is R6's warning in another domain: numeric coincidence is not quotation, and neither is textual
coincidence. Sharing a dimension is a claim expressed by a shared address.

## 3. A release needs an operation that pins the vocabulary state

The term's birth operation identifies the term, but it does **not** identify a later vocabulary
state containing terms and definitions added after that birth. §5.10's selector also needs a state
at which to fold the foreign store. Conflating those two names makes the first term's birth
accidentally mean “latest vocabulary,” which is precisely the moving-reference behaviour §5.9
refuses.

Each vocabulary therefore has an ordinary **release cell**. Publishing a release touches that cell
last — a `SetValue` carrying the release label is sufficient — after all term and definition edits.
The resulting operation has two roles already supported by the model:

- `denseOf(releaseOp)` resolves to the release cell, so it is a valid §5.10 selector root; and
- `releaseOp.produces` is the exact foreign state the quotation folds.

The publication DTO is not stored as a new record:

```cpp
struct PublishedVocabulary {
  GlobalOpRef releaseCell;    // birth op: stable identity of the release cell
  GlobalDocumentState state;  // pinned publication snapshot
  GlobalOpRef dimensions;     // birth op of the d.dims cell
};
```

It supplies §5.10's rank root, dimension and independent state pin. The release cell links posward
on `d.dims` to the first published term. Definitions, provenance, schemas and examples may hang from
terms on ordinary ranks (`d.notes`, `d.schemas`, or vocabulary-defined dimensions); the core
mechanism assigns none of them privileged meaning.

Publishing another release edits the same release cell after the vocabulary changes. Existing
adoptions keep their old `GlobalDocumentState`, even though `releaseCell` identity is unchanged.
Updating is one authored repoint of the quotation, with the previous release still in the quotation
head's R7 history — the pin-and-adopt ruling from §5.10, not automatic remote configuration.

## 4. Filing a term for local use

The store-level helper is conceptually small:

```cpp
struct AdoptedDimension {
  MicroversionId version;
  zigzag::DimRef local;
};

[[nodiscard]] AdoptedDimension
adoptPublishedDimension(const MicroversionId &parent,
                        const GlobalOpRef &term);
```

It performs two existing acts:

1. localise the term through §5.5 and mint or reuse its persistent placeholder; and
1. put that placeholder on this store's `d.dims` rank, making it discoverable by
   `dimensions()`/`dimensionNamed()` and valid as a `DimRef`.

The helper **interns by `GlobalOpRef`**. Filing Alice's `supports` twice must return the same local
placeholder, or one foreign dimension becomes two local dimensions that compare unequal. The
interning map is a replay product, not a new mutable table: rebuild it from `ExternRef` cells and
their `d.dims` membership, in the same spirit as §5.4's registry index and `Manifold::byRef`.

With §5.5's final shape, the placeholder is a member of the foreign scroll cell's `d.scroll-refs`
rank and carries the canonical operation name as descriptor content. The vocabulary adds no
alternate storage path.

Using the result is an ordinary call:

```cpp
store.setLink(parent, subject, adopted.local, POS, object);
```

The first use therefore costs one placeholder `MakeCell`, one `SetLink` onto local `d.dims`, and the
semantic `SetLink` the author intended. Later uses cost only the semantic operation.

## 5. Federation binds a set, with provenance

§5.7 establishes that a bound dimension across a tissue is a set containing one local `DimRef` per
attached space and records how the members were grouped. Published vocabularies install stable
`SharedIdentity` evidence for that existing extension point:

```text
Alice local placeholder ──> GlobalOpRef(V/supports) <── Bob local placeholder
              Alice d.17  ∈ bound set ∋  Bob d.4
```

The federation resolver groups placeholders by the resolved term `GlobalOpRef`, then records the
per-space mapping consumed by `dimIn(space, boundDimension)`. It must also retain the binding mode
§5.7 requires:

| binding mode     | evidence                                       | interpretation                         |
| ---------------- | ---------------------------------------------- | -------------------------------------- |
| `SharedIdentity` | placeholders resolve to one term `GlobalOpRef` | the authors cited the same dimension   |
| `NameMatch`      | labels compare equal                           | a reader chose an explicit convenience |

`NameMatch` is permitted and visible, never silently upgraded to `SharedIdentity`. A UI may offer
“these look alike; bind them?”, but accepting that offer is view policy and does not rewrite either
document. Persistent equivalence requires publishing or citing a shared term.

The vocabulary release is not the binding key. Releases pin definitions and catalogue membership;
the term's birth address is what lets the same dimension survive from release 1 to release 2.

## 6. What this does not collapse

- **A dimension is not a `LinkType`.** `LinkType::Disagreement` remains a butterfly-link type over
  spans. A published `refutes` term is a dimension cell used by Structure links. A vocabulary may
  document a relationship between them, but the runtime infers none.
- **A vocabulary is not a global registry.** Authors may publish competing argumentation
  vocabularies, cite both, or translate between them with ordinary cells and links. There is no
  canonical `supports` baked into an enum.
- **A vocabulary is not an ontology reasoner.** Inverses, transitivity, domain/range constraints and
  validation are data or Vortex/VQL programs over the terms. The fold remains allocation-free and
  applies no semantic rules.
- **Adoption is not tracking.** The release is pinned. Discovering a newer release may produce a
  notice; accepting it is an authored quotation update.

## 7. Phasing

1. **Publication convention and DTO** (§3), plus a helper that seals a release by touching its root
   last. No resolver and no federation required.
1. **Vocabulary adoption** as a §5.10 `rank` selector, with an in-memory `ForeignSource`. This is
   the catalogue and definition-reading path.
1. **Term filing** (§4): intern the §5.5 placeholder and place it on local `d.dims`.
1. **Shared-identity integration** (§5) in §5.7's existing bound-set API, retaining binding
   provenance.
1. **Presentation:** qualified labels, release information, unresolved states, and the explicit
   name-binding affordance. No automatic adoption or rebinding.

Phases 1–3 make published vocabularies useful in one store. Phase 4 supplies the trustworthy
cross-store identity rule that §5.7 deliberately leaves as an extension point.

## 8. Tests

- **`aVocabularyReleasePinsItsWholeRank`** — add a term after release 1, publish release 2, and
  assert quotations of the two releases materialise different `d.dims` ranks. This catches using a
  term's birth as the vocabulary state.
- **`adoptingAVocabularyDoesNotFileEveryTerm`** — materialise a large catalogue and assert the local
  persistent store has only the quotation machinery, with no placeholder per member.
- **`usingAPublishedTermMakesItALocalDimension`** — file `supports`, reload, and use the returned
  `DimRef` in `Store::setLink`; the rank walks and `refusedOps() == 0`.
- **`filingOneTermTwiceReusesItsPlaceholder`** — one `GlobalOpRef`, one local dimension cell. The
  identity invariant from §4.
- **`equalNamesDoNotBindByIdentity`** — two vocabulary stores mint cells named `supports`; attach
  both and assert two bound sets unless `NameMatch` is requested explicitly.
- **`sharedPublishedIdentityBindsAcrossStores`** — two stores file the same published term, federate
  them, and assert `dimIn` returns each store's local placeholder in one `SharedIdentity` set.
- **`renamingATermPreservesItsIdentity`** — edit the term's label in a later release; old and new
  catalogues render different labels while documents using the term remain identity-bound.
- **`replacingATermDoesNotHijackExistingBindings`** — mint a successor with the old spelling and
  assert existing documents still bind the original address.
- **`anUnavailableVocabularyIsAVisibleCitation`** — the release cannot be fetched: the quotation
  head remains visible, `refusedOps() == 0`, and no guessed name binding occurs.
- **`updatingAVocabularyIsAnAuthoredRepoint`** — adopt release 2 and assert the quotation head's R7
  history contains both release references while release 1 still materialises when scrubbed.

## 9. Risk

**The storage work is small and inherited.** No new node field, verb, wire record or fold rule is
introduced. The only persistent cells beyond §5.10 are the §5.5 placeholders for terms actually
used, plus ordinary links onto `d.dims`.

**The main risk is false equivalence.** A fallback that quietly groups dimensions by rendered text
will work in every demo and be wrong in the first docuverse where two communities use the same word
differently. The binding-mode provenance and the `equalNamesDoNotBindByIdentity` test are the guard.

**The second risk is confusing term identity with release identity.** A term must survive a release
while a release must pin a whole store state. One `GlobalOpRef` cannot play both roles unless the
term happens to be edited last, an ordering accident that fails as soon as another term changes. The
release cell in §3 makes the distinction structural.

**Implementation order matters.** §5.7 must expose provenance-bearing bound sets before this step
adds `SharedIdentity`, while §5.10 must expose a vocabulary before it can be adopted. Keeping the
generic federation API earlier and the vocabulary-specific evidence here removes a dependency cycle
without weakening identity.

```sh
make -j$(nproc) test TEST_FILTER='*Vocab*:*Quot*:*Extern*:*Federat*:*Dimension*'
make -j$(nproc) test && make format-check && make lint
```
