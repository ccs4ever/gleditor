# 5.4 — The store's tables as cells

Implementation plan for §5.4 of [`structure-hyperop-vision.md`](../structure-hyperop-vision.md).
**Status:** proposed. **Depends on:** [§5.2](5.02-operation-handles.md) for operation handles and
[§5.3](5.03-editions-rank.md) for the editions rank. **Provides:** the final `d.scrolls` registry
and replay indexes that §5.5 uses directly, avoiding a temporary `externals` side table and a second
migration.

`store.tables` holds five sections in a versioned bencode container beside `ops.nodes`. The
convergence put them there deliberately, in R11 and again at migration step 13, on the reasoning
that "there is no reason a scroll registry and a link table are separate artefacts other than that
they were written at different times; both are **per-store side tables replayed at load**". This
section takes the last step that sentence implies: a thing replayed at load is an operation.

## 1. The defect, in four words

AGENTS.md says of the five sections: **"None has a hypertime name."**

So a link, an annotation and a designated version have no *when*, no branch, no author, no R7
micro-history, and cannot be quoted or transcluded. A `SetLink` between two cells has all of that; a
xanalink between two documents has none of it. Which is the layout contradicting the sentence
`ops.hpp` quotes at line 245 — "**THE AUTHOR'S LINKS ARE NO DIFFERENT FROM ANYONE ELSE'S IN
IMPLEMENTATION**" — for the author's own links, one level below where anyone would look.

Three smaller things are wrong with it, and they are the ones that cost maintenance rather than
meaning:

- **Document authority is split.** AGENTS' "one writer" rule concerns `ops.nodes` itself;
  `SegmentedOpsSpool::writeSegmentFile()` alone produces that file. It does not mean the store has
  one output file: `Store::save()` also calls `writeStoreTables()` (`store.cpp:1395`, `:1431`).
  Moving document facts into operations removes the split authority but does not by itself make the
  two-file save atomic.
- **It is the last mutable artefact.** `store.tables` is rewritten whole on every save, sitting
  beside an append-only, Merkle-sealed log that is never rewritten at all.
- **Publication is two streams.** The operations go over the wire as `CompactBinaryV4`; whatever the
  tables hold has to travel some other way or not at all.

## 2. What moves, and what does not

| section (`store_tables.hpp:104-119`) | moves?                       | why                                                                                                                  |
| ------------------------------------ | ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `versionAnnotations`                 | **yes**                      | an annotation is a remark by a person about a state; it wants an author and a date more than anything else here does |
| `currentVersions`                    | **yes**                      | "in the order they were set" is a rank wearing a `std::vector`                                                       |
| `links`                              | **yes**                      | the load-bearing one: §1's contradiction is this row                                                                 |
| `scrolls`                            | **yes**, with §4's bootstrap | and it is what lets §5.5 drop a table                                                                                |
| `localSegments`                      | **no**                       | where bytes sit *on this machine*                                                                                    |
| `storeName`                          | **no**                       | the bootstrap needs a name before it can read anything                                                               |

**`localSegments` staying is not an exception grudgingly made; it is the line this section draws.**
It holds paths and info hashes — facts about a deployment, not about a document. AGENTS already
notes a store "is not portable alone: it needs the permascroll it was written against", which is
that distinction stated from the other side. An operation is published; a path is not, and a
hypertime-named operation carrying one would publish a filesystem. **Rule: an operation records what
the document is, never where this copy of it happens to live.**

## 3. The shapes, and no new verb

Each is an ordinary `MakeCell` plus links. **No new `OpKind`, no new `StructureVerb`**, which is the
answer this arc keeps arriving at: R12 dissolved `MakeDim` because "a dimension is a cell so minting
one is `MakeCell` plus `SetLink`", and [§5.5 §4](5.05-extern-refs.md) refused a `SetExternLink`
because "the link is local. Only its target stands for something remote."

- **A scroll** is a cell whose content is its global key, on a `d.scrolls` rank off home. Its
  `ScrollId` belongs in the derived registry index, not immutable `valueBits`: local ids are
  renumbered when a publication is ingested. The cell records identity; the replay product assigns
  the local fast-path id.
- **An annotation** is a cell whose content is the description, on `d.notes` off an
  [§5.2](5.02-operation-handles.md) `OpHandle` cell naming the microversion, with alias and tag on
  their own ranks. Keep an explicit wall-clock timestamp if the UI promises one: a `MicroversionId`
  names a state but does not encode time, and an operation alone supplies no authenticated clock
  reading. Treat a claimed time as signed metadata, not as proof of when an edit happened.
- **A designated current version** is an [§5.3](5.03-editions-rank.md) edition named `current`, on
  the `d.editions` rank. `currentVersions`' ordering is the rank's ordering, so the vector's one
  real property is preserved by the thing replacing it.
- **A link** is a cell with endpoint cells on `d.from` and `d.to` that carry ordered, durable
  `GlobalSpan` runs (including every span of a multi-span end), and its type as a cell on
  `d.linktype`. `UniversalLinkEnd` is derived for a particular view: its document index and
  `CellRef` offsets are not a portable endpoint address. The link id becomes the cell's own ref,
  which is the `MakeCell`'s index — so link identity stops being a `std::uint64_t` counter and
  becomes an address (R4), nameable across documents through §5.5 like anything else. Preserve end
  ordering, empty versus absent ends, and the existing `Link` type/tier/owner/curator fields during
  conversion; verify round-trip equivalence before removing the side-table reader.

That last one is the payoff worth stating plainly: **once a link is a cell, another author's link
set over your document is just their cells over your cells**, which is precisely what §5.12 wants
and currently has no way to express, because you cannot publish a row of somebody's bencode.

## 4. The bootstrap rule

Reading a cell's content needs the scroll registry to resolve a `ScrollId`. If the registry is
itself cells, reading it needs the registry. The circle has to be cut by authenticated publication
metadata, not by an assumption about the machine doing the opening.

**Ruling: `AUTHORSHIP.tsv` is the bootstrap scroll for a published store.** The author signs it and
the publication torrent seals it. It carries the globalized link for the author's permascroll — the
same permascroll that was scroll 0 while the author wrote the store — so an opener can establish
that mapping before replaying any registry cell. It is not the opener's scroll 0, and the author
need not have the same local `ScrollId` on two machines.

The canonical provenance carries a `permascroll` row containing that global scroll key. It cannot be
derived from `publisher` and `salt`: those name the document publication, while the permascroll is
sovereign across all of the author's documents. A publication without the row predates this
bootstrap and must be regenerated before its registry moves to cells; the reader never substitutes
an unsigned side-channel value. The signature covers the exact TSV bytes.

Opening a publication is therefore a rooted dependency walk:

1. Verify the signature and torrent membership of `AUTHORSHIP.tsv`, expose its bytes through a
   bootstrap scroll handle, and install the author's global permascroll mapping.
1. Walk `d.scrolls`. A registry cell may be readable through any mapping already established, not
   only through local id 0; each successful entry can make further cells readable.
1. Repeat until the rank is resolved. Refuse an unresolved dependency cycle or a missing root,
   naming the cells and scroll ids involved, rather than making success depend on operation order.
1. Fold everything else through the completed registry.

An unpublished local store has the simpler root: its attached `UserPermascroll` resolves local
scroll 0 directly. Publication globalizes that root and records it in `AUTHORSHIP.tsv`; opening a
published store never silently substitutes the opener's permascroll.

This is the same kind of explicit root as manifold genesis: `home` and `d.dims` exist before the
first structural link because that link needs them to be nameable (`manifold.cpp:235-239`, R12). The
difference is that a publication root is authenticated data rather than a local convention.

### 4.1 Provenance as an arena view

`AUTHORSHIP.tsv` is also useful document data: author, publisher, title, publication time,
fingerprints, hashes and the globalized permascroll link should be addressable like everything else.
They do **not** become persistent `Structure` operations. They describe the signed publication
envelope, not edits made by the author, and minting them into the store would make opening a
publication change its history.

Add the Store-backed arena construction path here. A `Store` opened from a publication retains the
verified `SignedProvenance` and the authenticated `AUTHORSHIP.tsv` bootstrap source. Creating an
`ArenaManifold` from that store overlays its base `Manifold` and projects one ephemeral authorship
root plus ephemeral field cells. The root is reachable from arena home on `d.authorship`; fields are
ranks on canonical dimensions such as `d.author`, `d.email`, `d.publisher`, `d.permascroll`,
`d.published` and `d.signature`. Unknown TSV keys remain visible on derived field dimensions so a
new provenance field does not disappear in an older reader.

Every projected ref carries `ephemeralBit`, every decoded field value lives in the arena's scratch
scroll, and a source link points back to the authenticated bootstrap scroll. Dropping the arena
drops the view. Promotion excludes these derived cells unless a caller explicitly copies their
content into newly authored cells; it must never turn signed metadata into operations attributed to
the opener. An unverified or tampered `AUTHORSHIP.tsv` produces no provenance cells and fails the
publication open that requested them.

## 5. The index is a replay product, not a lookup structure

Today `scrolls` is a vector indexed by `ScrollId` and `links` is a `std::map` by id. As ranks, a
lookup would be a walk, and a walk per span read would be fatal. **The resolution is the framing,
not the data structure.**

The convergence's own §3 says a `Version` is the first replay product of the ops spool and a
`Manifold` is "a *second replay product* of the same ops spool". This makes the registry and the
link index a **third**: the operations are the truth, and the fold emits the hash map, exactly as it
emits `byRef` today. Nothing in the hot path walks a rank, and the tables stop being an artefact
that can disagree with the operations — because there is nothing left for them to disagree with.

It also inherits the honesty mechanism. `verifyAgainstFullRebuild()` exists because a folded product
can drift from a cold rebuild; the registry gets the same check for free, and a store whose index
does not match its operations becomes a detectable state rather than a silent one.

## 6. The handoff to §5.5

An earlier extern-reference draft proposed an `externals` section indexed from a placeholder's
`value`. This build order refuses that temporary representation. §5.5 instead uses two ranks:

```text
home ──d.scrolls──> [ scroll S ]
                       │
                       └──d.scroll-refs──> [ placeholder P1 ] ──> [ P2 ]
```

`d.scrolls` enumerates scroll identities. A separate `d.scroll-refs` rank is anchored at each scroll
cell because a ZigZag dimension has only one positive and one negative neighbour: many placeholders
cannot all point directly at the same scroll cell, and reusing `d.scrolls` would also destroy the
registry rank. The replay index maps every placeholder on that rank to S's derived `ScrollId` in
O(1).

The placeholder's foreign `MicroversionId` is variable length and therefore cannot fit in its 64-bit
`value`; §5.5 stores its canonical text as ordinary cell content. Resolution may read those small
descriptor bytes, but the fold remains I/O-free. No `externals` table, duplicate `Store::externals`
name, or impossible `MicroversionId`-in-`value` encoding is introduced.

## 7. Price

- **Operations.** A store with ten thousand links gains roughly that many `MakeCell`s plus their
  links — tens of thousands of 64-byte nodes against a ceiling of 134,217,727. Not a constraint;
  worth measuring against fold time rather than against the ceiling.
- **Fold time.** Every open replays more. The fold is already the load path's cost and is linear in
  operations, so this is a percentage rather than a shape change — but it is the number that decides
  whether the section is worth it, and it should be taken on the KJV store with
  `tools/benchmark-kjv-load.py` before phase 3.
- **Store directory.** `ops.nodes` plus a much smaller `store.tables` holding only the store name
  and `localSegments`. This reduces duplicated document authority, but does not make `Store::save()`
  atomic or leave one physical writer: it still writes two files. Specify a crash-safe commit order
  and recovery rule separately; do not claim this migration alone fixes torn saves.
- **The window is now.** R11 "is void at first external publication", and this is a format change of
  exactly the kind R11 exists to license. Every store regenerates from its inputs today; the first
  time somebody outside this repository has a document they care about, the same change costs a
  migration. If the answer is yes, it is much cheaper now than later, and that is a scheduling fact
  rather than an argument for doing it.

## 8. Phasing

Each phase moves one section and deletes its container code in the same commit, so the tree never
holds two readers for one fact.

1. **`versionAnnotations`** — the smallest, with no bootstrap and no hot path. Proves the shape.
1. **`currentVersions` as a `current` edition**, over §5.3.
1. **`scrolls`**, with §4's `AUTHORSHIP.tsv` root and §5's registry-as-replay-product. The hard one;
   benchmark here.
1. **The arena provenance view** — retain verified publication provenance on the opened `Store` and
   project it as ephemeral cells whenever a Store-backed `ArenaManifold` is created.
1. **`links`** — the largest and the one §1 is about. Link ids become cell refs, which touches every
   link consumer.
1. **The §5.5 handoff:** expose the registry replay API and `d.scroll-refs` membership index that
   persistent extern placeholders consume.

## 9. Tests

- **`anAnnotationKeepsStateSeparateFromClaimedTime`** — the handle names the annotated state; signed
  timestamp metadata, when present, remains a distinct field and is never inferred from a
  `MicroversionId`.
- **`aLinkIsACellWithAnAddress`** — a link's id is its `MakeCell` index, and `opRefOf()` names it
  across documents. The §3 payoff.
- **`aMultiSpanLinkSurvivesPublicationAndTransclusion`** — both ordered end span runs, link
  metadata, and derived `UniversalLinkEnd` projections agree before and after save, publication,
  adoption, and a transcluded display.
- **`anotherAuthorsLinkSetFoldsOverMine`** — §3's last paragraph and §5.12's prerequisite: fold a
  second store's link cells against this document's cells and assert both sets are readable and
  distinguishable.
- **`publishedHistoryBootstrapsThroughAuthorship`** — open another author's publication without
  installing their permascroll as the opener's scroll 0; the signed `AUTHORSHIP.tsv` global key is
  sufficient to resolve its registry.
- **`aRegistryCellMayUseAnAlreadyMappedNonZeroScroll`** and
  **`anUnrootedRegistryDependencyIsRefused`** — §4's dependency walk and its loud refusal.
- **`verifiedAuthorshipAppearsAsEphemeralArenaCells`** — a Store-backed arena exposes all known and
  unknown provenance rows, linked to their authenticated source, and every projected ref carries
  `ephemeralBit`.
- **`authorshipProjectionNeverMintsPersistentOps`** and **`tamperedAuthorshipIsNotProjected`** —
  building and dropping the view leaves the store's op count unchanged, while failed verification
  prevents both publication open and projection.
- **`theFoldedRegistryMatchesAColdRebuild`** — §5's honesty check, the `verifyAgainstFullRebuild()`
  analogue.
- **`aStoreDirectoryHoldsOnlyOpsAndLocalFacts`** — §7: after phase 4, `store.tables` contains the
  store name and `localSegments` and nothing else.
- **`aPlaceholderLinksToItsScrollCell`** — §6, and the join to §5.5 and §5.7: persistent and
  ephemeral foreign references have one shape.
- **`kjvLoadTimeIsMeasuredBeforeAndAfter`** — a benchmark, not an assertion, per §7.

## 10. Risk

**The bootstrap is where a subtle bug would live.** The failure mode is a publication that opens on
the author's machine because its local scroll 0 happens to resolve, then opens empty elsewhere. §4
removes that ambient dependency: resolution starts at signed `AUTHORSHIP.tsv`, and the dependency
walk either reaches every registry cell or reports the unresolved set. The remote-open and refusal
tests are the guards and land with the scroll phase, not after it.

**The provenance projection must not counterfeit history.** Arena cells are derived presentation,
not claims that the opener authored new operations. The `ephemeralBit`, unchanged-op-count and
tampered-signature tests make that boundary executable; promotion must preserve it explicitly.

**Link ids becoming cell refs touches every link consumer.** `Link` records are keyed by
`std::uint64_t` today and read across `link_layout.cpp`, `link_discovery.cpp`, `beams.cpp`,
`mutable_link.cpp` and the bridge. The change is mechanical but wide, and it is the phase most
likely to want splitting.

**Fold time is the falsifiable point.** If replaying the tables costs a materially slower open on
the KJV store, the section is wrong and the tables should stay a container — §7 says where to
measure and phase 3 is the gate. Stated in R12's style so the trigger is recorded rather than
discovered.

**The order is the risk control:** §5.5 follows immediately and builds only the final rank-backed
shape. Reversing them would create a side-table reader, writer and migration solely to delete them.

```sh
make -j$(nproc) test TEST_FILTER='*StoreTables*:*Scroll*:*Link*:*Annotation*:*Extern*'
make -j$(nproc) test && make format-check && make lint
```
