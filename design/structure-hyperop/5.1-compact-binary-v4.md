# 5.1 — `CompactBinaryV4`: carry a Structure operation's chain on the wire

Implementation plan for §5.1 of [`structure-hyperop-vision.md`](../structure-hyperop-vision.md).
**Status:** ready to implement. **Prerequisite for:** §5.6–§5.10, and for publishing a ZigZag slice
at all. **Appends no operations, changes no on-disk store layout, invalidates no fixture.**

## 1. The defect, in one paragraph

`Store::setLink()` chains an operation to the previous one on the same cell by name
(`op.source = opsSpool.idOf(previous)`, `store.cpp:484-486`), and `opRecords()` hands that name back
faithfully (`store.cpp:1326-1327`). The binary writer then drops it: the `BinStructure` case
(`binary_ops.cpp:236-266`) writes tag, `produces`, `flags`, `to`, `link`, the three span fields and
`value`, and never `op.source` — where the `Transclude` case twenty lines above does
(`binary_ops.cpp:212`). The reader (`:409-430`) therefore leaves `source` default-constructed;
`putOp` turns that into `sourceOpIndex == 0` (`store.cpp:118`); and `applyStructure` resolves
`denseOf(0)` to `noDense` and refuses the operation (`manifold.cpp:245-250`, `:307-310`,
`:320-323`).

**A published slice arrives as isolated cells with no links, and the only trace is a counter.** It
has gone unnoticed because `MakeCell` reads no chain — a genesis-only slice round-trips perfectly —
and because the one round-trip test builds its `SetLink` with `source` left zero and asserts only on
the fields that survive (`tests/xudu/binary_ops.cpp:390-442`). It passes vacuously.

`Splice` is the same wound already bandaged: the writer refuses it by name rather than corrupting it
(`binary_ops.cpp:245-250`), because the record has nowhere to put `at` or `length` either.

## 2. Scope, after checking §3's premises against the code

§3 of the vision note listed four things for this bump. Two do not survive inspection, and the plan
says so rather than implementing a no-op.

| §3 item                        | verdict                                                                                                                                  |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| carry `op.source`              | **in scope.** The defect above.                                                                                                          |
| carry `Splice`'s `at`/`length` | **in scope.** Retires the refusal and closes U3.4's first half.                                                                          |
| widen the wire kind field      | **not needed — already done.** V3 widened it to four bits; `BinStructure = 7` is the eighth of sixteen values, with eight free after it. |
| a skippable extension record   | **recommended deferral.** See §6; this is the one open decision.                                                                         |

One item **joined** the list after this plan was written: an `OpHandle` cell's target, added by
[`5.4`](5.4-operation-handles.md) §2. It is a `value` carrying an operation index, so it renumbers
on the reader exactly as `source` would, and a published handle would silently name a *different*
operation. Same fix, same mechanism: when `valueKindOf(flags) == ValueKind::OpHandle`, write the
target as a `MicroversionId` and let `indexOf()` re-localise it. Folded in here rather than bumped
to a V5, since neither section is built yet.

A fifth item, `storeToLinkPackage()` publishing a cell under its first span only (U3.4), is **out of
scope**: that is `LinkPackage`'s shape and its own wire format in `link_package.cpp`, not the ops
spool. Moving both versions in lockstep would couple two formats that have no reason to agree. It is
still owed, and §7 records it.

What *is* full is the **tag byte** — four kind bits plus four flags, held by a `static_assert`
(`binary_ops.cpp:29-37`). A new *flag* needs a second byte or a version. This plan needs no new
flag.

## 3. The encoding

Version 4 changes the `BinStructure` record and nothing else. Every other kind, the varint encoding,
the branch-ordinal escape and the field order are untouched.

```text
V3  tag [produces] flags to link span.scroll span.start span.length value
V4  tag [produces] flags to link span.scroll span.start span.length value
                                                                     source
                                                                     [at length]       <- iff verb == Splice
                                                                     [target-as-name]  <- iff valueKind == OpHandle
```

Three decisions, each with its reason:

- **The new fields go at the end.** The existing read sequence is untouched, so the diff is purely
  additive and a transcription slip in the middle of the record cannot happen.
- **`source` is written unconditionally, for all four verbs.** A `MakeCell` is genesis for its own
  cell and its `source` should always be zero, but writing conditionally on that invariant would
  turn any future violation into a silent drop — the exact failure class this bump exists to close.
  Correctness by construction is worth the few bytes on a format that is not hot.
- **`at` and `length` are written only for `Splice`, keyed off the verb the reader has already
  decoded.** The reader reads `flags` as the first field after the tag, so it knows the verb before
  it needs to know whether two more varints follow. No new flag bit, no ambiguity, and zero cost for
  the other three verbs. Note that `FLAG_AT_EQUALS_START` stays unset for `BinStructure`: for a
  `Splice`, `at` is an offset inside the cell's content and `span.start` is a permascroll address,
  so comparing them is meaningless.

The reader needs no other change. `putOp` already re-localises a `MicroversionId` through
`opsSpool.indexOf()` (`store.cpp:118`), which is R4-correct by construction — the name survives a
seal, the index does not.

**The OSMIC text encoding is already complete and does not move.** `writeOsmicTextOpsSpool`
(`binary_ops.cpp:442-452`) emits every field of `Op` as a fixed column, `at`, `length` and `source`
among them. Only the binary format ever dropped them.

## 4. Steps

1. **Version constants.** Add `CompactBinaryV4 = 4` to `OpsSpoolVersion` (`binary_ops.hpp:34-58`)
   and `binaryOpsMagicV4 = "\x7fXOP\x04"`; re-point `binaryOpsMagic`. Extend `opsSpoolVersionName()`
   and `detectOpsSpoolVersion()` (`binary_ops.cpp:516-551`) so version 3 joins 1 and 2 in being
   **refused by number** — R11: bump, write the new shape, delete the old reader. Rewrite the enum's
   doc comment, which currently explains V3's widening as though it were the newest thing.
1. **Writer** (`binary_ops.cpp:236-266`). Delete the `Splice` refusal and its comment. After
   `writeVarint(out, op.value)`, add `writeMicroversionId(out, op.source)` and, when
   `StructureVerb::Splice == structureVerbOf(op.flags)`, `writeVarint(out, op.at)` and
   `writeVarint(out, op.length)`. Replace the "`at` is not written" comment with why it now is.
1. **Reader** (`binary_ops.cpp:409-430`). Mirror exactly: `readMicroversionId(in, op.source)` with a
   `throw` naming the field on failure, then the two conditional varints. Follow the surrounding
   house style — a truncated record throws `"malformed binary structure source"`, not a silent
   `return`, so a short read is not mistaken for end of stream.
1. **Tests** (§5).
1. **Documentation** (§7).

## 5. Tests

The first is the one that was missing and the reason the defect survived.

- **`aPublishedSliceFoldsWithItsLinksIntact`** (new, `tests/xudu/` — the end-to-end regression).
  Build a store with a genesis, a dimension, two cells, a `SetLink` between them, a `SetValue` and a
  `Splice`. Seal it, ingest through `historyFromSeal`/`applyOpsSegment`, `rebuildManifold()`, and
  assert **`refusedOps() == 0`** plus a link traversal and cell content that match the source
  manifold. Nothing in the tree currently publishes a Structure operation and folds on the ingested
  side; that gap is what made a vacuous unit test look like coverage.
- **`aStructureOpRoundTripsThroughBothEncodings`** (`:390-442`, de-vacuify). Set `source`, and set
  `at`/`length` on a `Splice` case; assert them in the `check` lambda. Its opening comment still
  says "Nothing emits one yet", which is no longer true — eight call sites emit Structure
  operations.
- **`aSpliceOperationSurvivesPublication`** (new). The refusal at `:245-250` becomes a round-trip: a
  `Splice` at a nonzero offset replacing a nonzero length arrives meaning the same thing.
- **`theVersionsThisBuildNoLongerReadsAreRefusedByNumber`** (`:294-326`, update). The loop becomes
  `{'\x01', '\x02', '\x03'}` and the expected substring becomes `"version 4"`.
- **`theTagByteGivesTheKindFourBitsAndTheFlagsTheRest`** (`:329`) should still pass untouched; if it
  does not, the tag byte was changed and it should not have been.
- **Check `spaceShrinkageExceedsEightyPercent`** (`:226`). If its corpus contains Structure
  operations the ratio moves slightly. Re-measure rather than relax the bound.
- **`tests/fuzz/fuzz_binary_ops.cpp`** drives `readOpsSpool` (`:22`) and should need no change,
  since it detects by magic. Confirm it does not pin a version.

## 6. The one open decision: the skippable extension record

§3 proposed a length-prefixed, skippable extension record in this bump, on the ground that R11's "no
compatibility shims" is about files on your own disk, not a wire two peers negotiate. That argument
is real. The recommendation is nonetheless to **defer it**, for two reasons:

- **§5.6 no longer needs it.** The ruling recorded there puts the variable-length part of a
  cross-store reference in `store.tables` — a bencode `externals` section mapping `GlobalOpRef` to a
  local placeholder — precisely so the 64-byte node and the ops wire stay fixed-shape. What §5.6
  adds to this record is a `GlobalOpRef` for placeholder `MakeCell`s, which is fixed-shape and can
  ride the same verb-conditional trick `Splice` uses here.
- **Nothing can test it.** With no writer emitting an extension, the only possible test is skipping
  a synthetic one — a mechanism maintained against a hypothesis.

Bundling it would also make a correctness fix harder to review. If you want it in this bump anyway,
it is a self-contained addition to §4 step 2/3 and does not change anything else in this plan.

## 8. Verification, risk, and blast radius

```sh
make -j$(nproc) test TEST_FILTER='BinaryOpsTest.*:*Publish*:*Manifold*'
make -j$(nproc) test
make format-check && make lint
```

**Blast radius is small and bounded.** Only six files name `CompactBinaryV3`:
`binary_ops.{hpp,cpp}`, `ops.hpp`, `tests/xudu/binary_ops.cpp`, `design/store-slice-convergence.md`,
`AGENTS.md`.

**No fixture is invalidated.** All seventeen checked-in `ops.export` files are OSMIC *text* (each
begins `1 insert`/`1 structure`/`1 transclude`), not binary, so nothing needs regenerating — unlike
a `CompactOpNode` layout change. `sizeof(CompactOpNode)` does not move, so `ops.nodes` and
`store.tables` are untouched and the three `static_assert`s are not in play.

**The one real risk** is a writer and reader that disagree about the conditional `Splice` fields,
which would surface as a misparse of every *subsequent* record in the stream rather than a local
failure. The end-to-end fold test in §5 is what catches it: a stream that desynchronises will not
produce a manifold equivalent to its source.

Rollback is a revert; nothing on disk will have been written in the new shape that cannot be
regenerated from its inputs.
