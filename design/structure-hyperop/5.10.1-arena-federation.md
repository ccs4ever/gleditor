# 5.10.1 — Arena federation: a tissue of manifolds, none of them copied

Implementation plan for the composition mechanism [§5.10](../structure-hyperop-vision.md) names and
does not specify. **Status:** proposed; the mechanism is half-built and the missing half is a cell
and a dimension. **Depends on:** nothing for phases 1–3. **Unblocks:** §5.10's overlay fold mode,
and it simplifies [§5.7](5.7-anthology-ranks.md), [§5.8](5.8-quoted-ranks.md) and VQL's multi-store
path, two of which are paying for its absence today by copying.

§5.10 says it is "last in the order only because it needs an overlay *fold mode* — composing two
manifolds at a tier — which nothing in the tree has yet." This is that fold mode. It is owed earlier
than §5.10, because composing manifolds is what a docuverse does at rest: a space of slices is a
*tissue* of deeply interconnected cells, and the tree currently renders a tissue by photocopying it.

## 1. What copying costs, in the code that does it

`MultiStoreCoordinator::addStore()` folds a store's manifold and hands it to `importManifold()`
(`vql/multi_store.cpp:101-160`), which mints one `dest.makeCell()` per source cell and re-links
every dimension in a second pass. Five documents in one VQL query is five whole manifolds copied
into one arena, per query.

The memory is the smaller half. **The copy discards identity.** `sourceToDest` is a local of that
function, so an imported cell has no route back to the `(store, operation index)` it came from.
Nothing downstream can form a `GlobalOpRef` for it, which means a cell in a composite arena cannot
be linked to, cited, overridden, or promoted as a reference — only re-minted as more copy.
[§5.7 §2](5.7-anthology-ranks.md) already draws the line this sits on: `importManifold` *reproduces*
where a quotation *quotes*, "and the tree currently has only the reproducing half."

[§5.8](5.8-quoted-ranks.md) §5, as planned, would add a second copier. Building that before this
note is building the reproducing half twice.

## 2. The mechanism is half-built

Two pieces are already in the tree and are exactly the two this needs.

**Reads already fall through.** `ArenaManifold::denseOf()` answers `noDense` for a ref it does not
hold, and every read delegates:

```cpp
const CellSlot *ArenaManifold::slot(const CellRef ref) const noexcept {
  const auto dense = denseOf(ref);
  if (noDense != dense) { return &slots_[dense]; }
  return nullptr == base_ ? nullptr : base_->slot(ref);   // arena_manifold.cpp:30-36
}
```

`linked()`, `contentOf()` and `dimensionsOf()` have the same shape (`:98-135`). That is federation
with exactly one foreign manifold, carrying the two properties the general case needs: reads
dispatch on ownership, and writes shadow rather than mutate.

**And `d.stores` already exists.** `MultiStoreCoordinator` mints a cell per attached store on a
`d.stores` rank off home — `StoreInfo::storeCell` is "Representative cell on coordinator's
`d.stores` rank" (`vql/multi_store.hpp:48`) — and VQL already addresses it, resolving `##NAME` as
`##/d.stores>[d.name = "NAME"]` (`:12`). The place to hang "which document is this from" is built,
queryable, and in production.

What is missing is only that a foreign cell is *copied* into the arena rather than *named* from it.

## 3. The ruling: a foreign cell is a proxy cell on `d.stores`

**A foreign cell is named by a proxy the arena mints: an ordinary arena cell whose `valueKind` says
it stands for a cell elsewhere, whose `valueBits` carry which space and which operation index, and
which links on `d.stores` to the cell representing its store.** Resolution is a slot read the caller
already did and one table index. `CellRef` does not change, no bits are stolen, and **identity never
rides in the name**.

Three things follow immediately, and they are the reason this is the right layer:

- **No ceiling of any kind.** Spaces are cells on a rank, so there are as many as a person mints.
  Nothing in the design counts documents.
- **Nothing collides.** A proxy has a local dense index like every other arena cell, so Alice's
  operation 87 and Bob's operation 87 are two proxies with two refs and no arithmetic keeps them
  apart — the arena's ordinary allocator does.
- **It is inspectable and queryable.** "What is this cell, and where is it from" is a link walk, so
  VQL can ask it with the syntax it already has, and a person can navigate it with the keys they use
  for everything else. A bit field answers the same question only to C++.

**The proxy is §5.6's placeholder, un-persisted**, and this is the coherence that settles it.
[§5.6](5.6-extern-refs.md) rules that a persistent reference to a foreign cell is "an ordinary
`MakeCell` with `ValueKind::ExternRef = 5` and the `externals` index in `value`". A proxy is an
ordinary arena `MakeCell` with `ValueKind::ExternRef` and the foreign reference in `value`. Same
shape, one ephemeral and one persistent, so **`promote()` on a proxy becomes a filing rather than a
translation**: the `d.stores` link and the value together are exactly what an `externals` entry
records.

### 3.1 A note on how this section reached its answer

The first draft of this plan packed a "which manifold" space id into spare bits of `CellRef`. It
then had to defend, in order: a fifteen-document ceiling, a runtime-tunable split to widen it, and a
new ruling to stop an exhausted arena from silently minting into another document's cell. Every one
of those was a problem *created by packing identity into the name* — and the whole time, the
structural answer was available, and half of it was already built and in production.

Recorded because the pattern is worth recognising earlier next time: **when a design starts needing
scarce-resource tricks — stolen bits, a wider scalar, a ceiling, a tunable — check whether more
cells and more dimensions solve it first.** The model is the tool. Reaching past it to the storage
layer is solving the problem at the wrong layer, and the tell is a limit that a person would have to
work around.

## 4. The proxy, as cells and dimensions

```text
home ──d.stores──> [ store cell: "alice/keymap" ]   ──d.stores──> [ store cell: "bob/notes" ]
                        ^                                              ^
              d.stores  │                                    d.stores  │
                        │                                              │
   [ proxy: ExternRef, value=(space 1, op 87) ]   [ proxy: ExternRef, value=(space 2, op 87) ]
```

**The store cell** is `StoreInfo::storeCell`, already minted on the `d.stores` rank. It gains what a
federation needs beside what VQL already puts there: the `Scroll` the store was sealed under, so
`opRefOf()` can name its cells globally. It is an ordinary cell, so it carries its label, role and
path as content and on ranks, exactly as it does now.

**The proxy cell** is minted on first reference to a foreign cell and never before — a walk that
never reaches a document mints nothing for it.

- `valueKind` is `ValueKind::ExternRef`, the kind §5.6 defines.
- `valueBits` holds the pair `(space, foreign operation index)`. It is 64 bits for a 32-bit index
  and a 32-bit space, which is past counting; and it is a *value* field whose whole purpose is to
  carry typed bits a query must not parse (R6), not a name with structure stolen from it.
- The `d.stores` link to the store cell is the **canonical** statement of where the cell is from.
  `valueBits`' copy of the space is the derived fast path, consistent by construction because one
  mint writes both — the same relationship R6 gives a scalar cell's text and its canonical bits.

**Identity is one proxy per foreign cell**, or `==` breaks: two proxies for Alice's cell 87 would
compare unequal while naming one cell. A per-space map from foreign index to proxy ref enforces it.
Because the map is per space, its key is a plain `std::uint32_t`; a space walked densely enough to
care can use a `std::vector<CellRef>` indexed by that key instead of a hash, at four bytes per
foreign cell, decided per space rather than globally.

### 4.1 Refused: packing the space into the ref

Kept because it was built out far enough to be worth not rebuilding, and because the measurements
are real.

**Stealing bits from `CellRef`** — a space id in the top bits below `ephemeralBit` — works, and
`isEphemeral()` would even keep its exact meaning, since a foreign operation index is precisely the
reference R4 forbids storing. It fails on what it costs to keep: a fixed four-bit field caps a view
at fifteen documents, which is a storage layout dictating how a person may read; making the split a
runtime policy removes the cap but adds a tunable that fails at runtime when chosen badly; and an
arena that exhausts its index field mints silently into the next space, aliasing one document's cell
onto another's, which needs its own refusal to prevent. Three defences for a problem that does not
exist if identity is not in the name.

**A home pointer in the `CellSlot`** cannot work at all:
`CellRef linked(CellRef, DimRef, DimVector)` takes and returns a bare ref (`manifold.hpp:230`), so
finding a cell's slot requires already knowing which manifold to ask. The collision happens before
any slot exists to consult.

**Widening `CellRef` to 64 bits** was measured rather than argued — the typedef was flipped and the
tree built:

| struct             | asserted                              | 32-bit | 64-bit            | assert fired?                          |
| ------------------ | ------------------------------------- | ------ | ----------------- | -------------------------------------- |
| `CompactOpNode`    | 64, align 64, `offsetof(value) == 56` | 64     | **64**            | **no — the on-disk node is untouched** |
| `DimLink`          | 12                                    | 12     | **24**            | yes                                    |
| `DirectedDim`      | 8, align 4                            | 8      | **16, align 8**   | yes, both                              |
| `CellSlot`         | 32                                    | 32     | *40 if corrected* | **no — silently stays 32**             |
| `TrailEntry`       | 40                                    | 40     | *48 if corrected* | **no**                                 |
| `UniversalLinkEnd` | 16                                    | 16     | *24 if corrected* | **no**                                 |

`CompactOpNode` survives because every field is an explicit fixed-width integer and it never names
`CellRef`, so the format does not move. The in-memory invariants do: a `CellSlot` at 32 is exactly
two per cache line and at 40 is one with twenty-four bytes wasted; a `DimLink` at 12 is five and a
third per line and at 24 is two and two thirds, on R12's own rank-hop path. `UniversalLinkEnd` is
*documented* as designed at sixteen bytes so the System V AMD64 ABI classifies it `INTEGER, INTEGER`
and passes it in two registers "with zero stack spills"; at twenty-four it spills. Per-cell memory
rises 45% at one dimension, **65% at three** (68 → 112 bytes), 81% at eight.

**And the build is the argument against it.** 586 errors across 52 files sounds like broad coverage;
it is four distinct problems, three of them one header assertion each repeated per translation unit,
plus **four real call sites** — two of which (`arena_manifold.cpp:230-231`, setting `birthOp` and
`lastOp`) are caught only because `CellSlot` happens to be brace-initialised there. The build runs
`-Wall -Wextra` with **no `-Wconversion`**, and most cell-ref *storage* is declared `std::uint32_t`
rather than `CellRef`: `CellSlot::birthOp` ("== this `CellRef`"), `UniversalLinkEnd::targetId`
("docIndex if Document, or `CellRef` if ZigzagCell", whose `forCell()` already casts),
`LinkRecord::fromTargetId`/`toTargetId`, and 165 `static_cast<std::uint32_t>` sites in the engine.
**The compiler stops at the sizes and waves the truncations through** — the worst division of labour
available. Scope, for the record: 91 files and 3,160 mentions of `CellRef`/`DimRef`, none of them in
`src/` or `include/`; the core library never sees one.

**What the proxy pays instead**, stated plainly so the trade is visible: one arena cell per
*touched* foreign cell, and one map lookup per hop that crosses into or within a foreign space.
Against a mask, that is slower. Against a ceiling, a tunable, a truncation audit and a silent
aliasing mode, it is the cheaper side — and §14 owes it a measurement.

## 5. The API

```cpp
/// One attached manifold, and what it takes to name a cell of it globally.
struct Space {
  const Manifold *manifold{nullptr};
  const xanadu::Store *store{nullptr};
  const xanadu::Scroll *sealedAs{nullptr}; ///< opRefOf() needs it; may be null locally
  CellRef storeCell{noCell};               ///< its cell on the d.stores rank
};

// on ArenaManifold, replacing the single base_
/// Attach @p space: mints its store cell on d.stores and answers its id.
std::uint32_t attach(Space space);
[[nodiscard]] const Space *spaceAt(std::uint32_t id) const noexcept;

/// The proxy naming (@p space, @p foreignIndex), minting it on first ask.
/// One proxy per foreign cell, so two asks answer the same ref.
CellRef proxyFor(std::uint32_t space, CellRef foreignIndex);

/// What a proxy stands for, or nothing for an ordinary arena cell.
struct ForeignRef { std::uint32_t space{0}; CellRef index{noCell}; };
[[nodiscard]] std::optional<ForeignRef> foreignOf(CellRef ref) const noexcept;

/// The (store, local ref) a proxy names — what promote() and opRefOf() want.
[[nodiscard]] std::optional<std::pair<const xanadu::Store *, CellRef>>
resolveForeign(CellRef ref) const noexcept;
```

`ArenaManifold(const Manifold *base)` stays, as sugar for attaching one space, so every existing
caller compiles unchanged and the copy-on-write-over-a-document case remains what it already is.

**A space is attached and never detached.** `ArenaManifold`'s contract already says a base "must not
be mutated while it is being read through — a shadow copies a cell, not a promise about one";
detaching is that hazard with the pointer removed instead of the bytes changed, and would leave
proxies naming nothing. Discard the arena instead, which `Mark`/`release` make cheap.

## 6. Reads: resolve, delegate, re-proxy

```cpp
CellRef ArenaManifold::linked(CellRef from, DimRef dim, DimVector dir) const noexcept {
  if (const auto foreign = foreignOf(from); foreign.has_value()) {
    const auto *const s = spaceAt(foreign->space);
    if (nullptr == s) { return noCell; }
    const auto answer = s->manifold->linked(foreign->index, dimIn(foreign->space, dim), dir);
    return noCell == answer ? noCell : proxyFor(foreign->space, answer);
  }
  ... // exactly what it does today
}
```

`foreignOf()` is a slot read and a `valueKind` test — the slot the caller's dispatch already fetched
— so the hop costs one map lookup for the answer's proxy and nothing else new.

Three properties worth stating:

- **`walkRank` needs no change.** It is a template over `ManifoldT` calling `m.linked(...)`
  (`manifold.hpp:119-157`), so a federated rank walks with the code a local one does.
- **A walk inside a space never leaves it.** A persistent cell's links can only name its own store's
  operation indices, because that is all `Store::setLink` can write. Crossings occur only where
  *this arena* wrote a link — an override, a quotation splice, a query result. **The tissue's seams
  are exactly the places somebody authored.**
- **The hop is a lookup, and R12 measured its yardstick** at 4.96 ns sequential and 21.02 ns
  scattered. This one owes the same courtesy before it is believed; see §14.

## 7. Bound dimensions become a set, and §5.9 stops being optional

R2 makes a dimension a cell, so Alice's `d.vars` and Bob's `d.vars` are two cells sharing a string.
Binding `d.vars` across a tissue binds a *set*: one dimension cell per attached space, which is what
`dimIn(space, dim)` above reads.

**The tree already does the name-keyed half.** `DimensionRegistry` is
`(const Store *, internedNameId) -> DimRef` (`dimension_registry.hpp:156`) — one name resolving to a
different `DimRef` per store is exactly its purpose. What it lacks is the notion of a bound set.

| how                | basis                                                                                 | when it is wrong                                       |
| ------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| by name            | both cells' content reads `d.vars`                                                    | your `d.vars` is not mine, and nothing says so         |
| by shared identity | both quote the same published dimension cell ([§5.9](../structure-hyperop-vision.md)) | it is not wrong; it is an address rather than a string |

`cloneMaster()` following `d.clone` negward is already the tree's "these are the same thing"
mechanism, and R12 uses it for exactly this: `d.meta-dims` entries are clone cells of the real
dimension cells so that "one dimension needs one identity however many cells link on it." Federation
is that sentence with *documents* in place of cells.

**Ruling: name-binding is allowed and must be visible.** A bound dimension records how each member
was bound, so a reader can tell "these documents share a dimension" from "these documents used the
same word." Silently treating a string match as an identity is the error `UserPermascroll` refuses
to make for content, where "sharing a coordinate is not an optimisation, it is a claim" (R6).

**So §5.9 published vocabularies is promoted from "deferred behind 5.8 by dependency, not by weight"
to a prerequisite for trustworthy federation.** It is what makes a cross-document dimension an
address.

## 8. Writes: shadowing and promotion

**Shadowing needs no special case at all**, which the ref-packing design could not say. A proxy is
an ordinary arena cell, so writing to a foreign cell shadows the proxy through the machinery that
already exists (`arena_manifold.cpp:329-360` maintains the reciprocal edge), and `shadow()`'s
comment that "the shadow's name is the base cell's ref… an overlaid cell is the *same* cell"
(`:400-401`) stays true unamended.

**`promote()` becomes a filing, and it is the part that makes this note pay.** Promotion already
"works by *mapping* refs rather than by being trusted with them: every arena ref is
`ephemeralBit`-tagged, so a promotion that forgot to translate one would be refused by
`Store::setLink()`". It gains one case:

| the ref names…           | promotes to                                                     |
| ------------------------ | --------------------------------------------------------------- |
| a cell this arena minted | a real `MakeCell`, as today                                     |
| a **proxy**              | a [§5.6](5.6-extern-refs.md) placeholder — the same cell, filed |

Because a proxy already *is* a `MakeCell` with `ValueKind::ExternRef` and a foreign reference in
`value`, promotion writes an `externals` entry from the `d.stores` link and the value, and stores
the cell. No translation, no second shape.

That is the chain made coherent: **federation is the ephemeral tissue; §5.6's extern reference is
the same cell made durable; §5.8's quotation is the authored statement that part of the tissue
belongs to your document; `promote()` is the road between them, which it already was.** It also
gives VQL something it cannot do today — promote a cross-store query answer as real links rather
than as a copy of somebody else's cells.

## 9. Proxy lifecycle

Proxies are ordinary arena cells, which is what makes this section short.

**They are minted lazily and reclaimed like everything else.** `mintSlot()` is a bump allocator —
`dense = slots_.size()` then a `push_back` (`arena_manifold.cpp:222`) — and `release()` ends with
`slots_.resize(m.cellCount)` (`:532`), so proxies minted under a mark vanish with it. The per-space
map must be truncated in step, which is one more length in `Mark`, in the shape the other seven
already have.

**Reclamation is LIFO only, and that is the arena's nature rather than this section's defect.**
There is no free list: a dead cell beneath a live one is unreclaimable and `slots_` grows
monotonically between resets, so the ref width bounds *total mints over an arena's life*. A
long-running session therefore **rotates the arena** — promote what is live, discard the rest, start
fresh — which is the compaction analogue and is expressible today. An arena is a scratchpad with
undo, not a heap; at the point it needs a heap's reclamation it should be a heap.

**Exhaustion must refuse loudly and by number.** `mintSlot()` has no check today, and `refOf(dense)`
is `ephemeralBit | dense`, so at 2³¹ mints the index runs into `ephemeralBit` itself. **Ruling:
`mintSlot()` refuses when the next dense index would reach `ephemeralBit`.** Note what this is *not*
any more: with no space field in the name, an exhausted arena cannot mint into another document's
cell. The failure is a refused allocation rather than a silent aliasing, which is the whole
difference between the two designs in one line.

**Reuse and stale refs.** Truncation recycles dense indices, so a ref outliving its `release()`
names a different cell — an ABA the arena has always had and which the discipline holds: a released
branch's refs do not outlive the release, which Vlog honours structurally. Federation does not
worsen it for foreign cells, because a foreign space's indices are its store's *operation* indices
and an ops spool is append-only, so **the foreign half never recycles**. Only the proxy does, along
with every other arena cell.

## 10. Progressive attachment: the granularity is a space, then a cell

- **Shape is per space.** There is no folding a suffix: `rebuildManifoldFromIndex()` walks the
  ancestral path from the beginning, and a replay missing its prefix is a different document. What
  *can* be lazy is which spaces are attached — do not fold Bob's store until navigation crosses into
  it — and under federation that is cheap, because attaching costs a fold rather than a copy.
- **Proxies are per cell**, minted on first reference, so an attached space costs nothing for the
  cells nobody visits.
- **Content is per cell and already lazy**: see [§5.8 §6](5.8-quoted-ranks.md), `Scroll`'s gaps
  (`scroll.hpp:263`) and `SwarmContentSource`'s deadline-bounded reads (`swarm.hpp:89-96`).

**Bound dimensions drive all three.** The bound set crossed with the view radius
(`Manifold::cellsWithinRadius`, and the bridge's configured radius) names the cells whose content to
prefetch, the proxies worth minting, and the crossings that make a space worth attaching. Switching
the bound dimension re-aims all of it. One signal, three consumers, no new state.

**Filtering the fold by bound dimension is refused.** It saves no I/O — every operation on the path
is read in order to walk it — and a dimension-filtered manifold is not `equivalentTo` a cold fold,
which costs `verifyAgainstFullRebuild()` the meaning R9 gave it.

## 11. What it does to the neighbours

- **VQL.** `addStore()` stops copying: it attaches a space and mints proxies on demand, with
  `d.stores` already the rank it puts store cells on. Queries keep identity across stores, so an
  answer is citable and promotable. Largest immediate win, in built code.
- **[§5.8](5.8-quoted-ranks.md).** The materialiser simplifies to attach-and-splice: the import pass
  and the span-translation step both disappear, because a quoted cell's spans stay in its own store
  and the reader resolves through the proxy. The selector survives, bounding *attachment* rather
  than a copy.
- **[§5.7](5.7-anthology-ranks.md).** An anthology resolves by attaching each member's space; its
  per-member states become per-space ones.
- **§5.10.** This is the composition substrate the overlay mode needs, and deliberately only that:
  federation says how two manifolds are read together and nothing about precedence. Which author
  wins where they disagree, and how a `ProminenceTier` orders them, stays §5.10's ruling.

## 12. Phasing

1. **The proxy.** `ValueKind::ExternRef` in an arena cell, `proxyFor()`, `foreignOf()`, the
   per-space map and its `Mark` length. One space, attached as `base_` is today. Pure refactor at
   the seams: every existing test must pass unchanged.
1. **N spaces**: `attach()`, store cells minted on `d.stores`, the delegating reads of §6.
1. **Bound dimension sets** (§7), with binding provenance recorded.
1. **`promote()` files a proxy as a placeholder** (§8), which needs [§5.6](5.6-extern-refs.md) phase
   1\.
1. **VQL stops copying** (§11) — the first production consumer, with existing tests to hold it
   honest.
1. **Progressive attachment** (§10), driven by the bound set and the view radius.

Phases 1–3 are self-contained and need no other section of the vision.

## 13. Tests

- **`twoStoresWithTheSameOperationIndexDoNotCollide`** — attach two stores each with a cell at
  operation 87 and assert two distinct proxies resolving to different cells. Inexpressible today,
  which is why it is first.
- **`aProxyIsMintedOncePerForeignCell`** — `proxyFor()` twice answers the same ref, so `==` means
  what it says. The identity invariant of §4.
- **`aProxyNamesItsStoreOnDStores`** — walk `d.stores` from a proxy and arrive at the right store
  cell; the structural claim, exercised the way a user would.
- **`aFederatedHopAnswersTheForeignCell`** and **`aWalkInsideASpaceNeverLeavesIt`** — §6's
  delegation and its seam property: walk a foreign rank of ten and assert every answer proxies the
  same space.
- **`aFederatedRefKeepsItsIdentity`** — recover a `GlobalOpRef` from a proxy and assert it names the
  foreign cell. **Fails today under `importManifold`**, and is the defect in §1.
- **`attachingAStoreCopiesNothing`** — assert the arena's own cell count is unchanged by attaching
  two documents, and rises only by the cells actually walked. The point of the note, as two numbers.
- **`shadowingAForeignCellNeedsNoSpecialCase`** — write through a proxy and assert the ordinary
  copy-on-write path and reciprocal edge, unamended.
- **`promotingAProxyFilesAPlaceholder`** — §8's table, and the join to §5.6: assert the promoted
  cell is the same shape the proxy already had.
- **`aBoundDimensionResolvesPerSpace`** and **`aBoundDimensionRecordsHowItWasBound`** — §7's ruling.
- **`proxiesVanishWithTheirMark`** — §9: mint proxies under a mark, release, and assert both the
  slots and the per-space map are back where they were.
- **`aMintAtTheRefCeilingIsRefused`** — §9's ruling: the refusal names the limit rather than
  returning a ref that reads as something else.
- **`theFederatedHopCostIsMeasured`** — a benchmark, not an assertion, against R12's 4.96 ns
  sequential and 21.02 ns scattered. R12 named the size at which its own ruling should be revisited;
  this one should arrive with the same courtesy.

## 14. Risk

**The per-hop lookup is the one real unknown**, and it is the only place the refused ref-packing was
ahead. A map lookup per foreign hop against R12's 4.96 ns could be a material fraction. Mitigations
are in the design — the map is per space so its key is a plain `std::uint32_t`, and a densely walked
space can use a `std::vector<CellRef>` instead of a hash at four bytes per foreign cell — but the
number decides it, and it should be measured in phase 2 rather than at the end.

**Proxy churn is the memory shape to watch.** One arena cell per touched foreign cell is cheap for a
reading view and not obviously cheap for a VQL query that sweeps a corpus: a query touching a
million foreign cells mints a million proxies at 32 bytes plus links. That is still far less than
`importManifold`'s copy of everything, touched or not, but it is the case to benchmark, and the
answer if it bites is that a sweeping query wants its own arena and to discard it (§9).

**The enumeration hazard is real and is not caught by types.** `cellCount()` and `cells()` mean
"this arena's own", so a loop of the shape at `vortex_stdlib.cpp:966-969` —
`for (c = 1; c < cellCount(); ++c) refOf(c)` — enumerates minted cells and now enumerates *proxies*
among them, while still seeing nothing of a space's unvisited cells. Every such loop needs to say
whether it means "mine", "mine excluding proxies", or "all", and there are five in
`vortex_stdlib.cpp` alone. Same observation [§5.8 §8](5.8-quoted-ranks.md) makes about consumers
written against `Manifold::cells()`, arriving from the other direction.

**Not a risk but worth recording while it is in view:** §5.6 proposes a `store.tables` section named
`externals`, and `Store::externals` is already the scroll registry (`store.hpp:932`). Two different
things under one name in one class is a five-minute rename now and a confusing half-hour later.

```sh
make -j$(nproc) test TEST_FILTER='*Arena*:*Federat*:*Proxy*:*Manifold*:*VQL*:*MultiStore*:*Vortex*'

```
