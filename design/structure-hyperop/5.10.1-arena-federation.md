# 5.10.1 — Arena federation: a tissue of manifolds, none of them copied

Implementation plan for the composition mechanism [§5.10](../structure-hyperop-vision.md) names and
does not specify. **Status:** proposed; the mechanism is half-built already and the missing half is
an encoding decision plus a dispatch. **Depends on:** nothing, for phases 1–3. **Unblocks:** §5.10's
overlay fold mode, and it simplifies [§5.7](5.7-anthology-ranks.md), [§5.8](5.8-quoted-ranks.md) and
VQL's multi-store path, two of which are paying for its absence today by copying.

§5.10 says it is "last in the order only because it needs an overlay *fold mode* — composing two
manifolds at a tier — which nothing in the tree has yet." This is that fold mode. It turns out to be
owed earlier than §5.10, because composing manifolds is what a docuverse does at rest: a space of
slices is a *tissue* of deeply interconnected cells, and the tree currently renders a tissue by
photocopying it.

## 1. What copying costs, in the code that does it

`MultiStoreCoordinator::addStore()` folds a store's manifold and hands it to `importManifold()`
(`vql/multi_store.cpp:101-160`), which mints one `dest.makeCell()` per source cell and re-links
every dimension in a second pass. Five documents in one VQL query is five whole manifolds copied
into one arena, per query.

The memory is the smaller half of the cost. **The copy discards identity.** `sourceToDest` is a
local of that function, so an imported cell has no route back to the `(store, operation index)` it
came from. Nothing downstream can form a `GlobalOpRef` for it, which means a cell in a composite
arena cannot be linked to, cited, overridden, or promoted as a reference — only re-minted as more
copy. [§5.7 §2](5.7-anthology-ranks.md) already draws the line this sits on: `importManifold`
*reproduces* where a quotation *quotes*, "and the tree currently has only the reproducing half."

[§5.8](5.8-quoted-ranks.md) §5, as planned, would add a second copier: import the induced subgraph
of a selector's answer, translating spans on the way. Building that before this note is building the
reproducing half twice.

## 2. The mechanism is half-built: `ArenaManifold` is the one-space case

`ArenaManifold::denseOf()` answers `noDense` for a ref it does not hold, and **every** read falls
through to the base:

```cpp
const CellSlot *ArenaManifold::slot(const CellRef ref) const noexcept {
  const auto dense = denseOf(ref);
  if (noDense != dense) { return &slots_[dense]; }
  return nullptr == base_ ? nullptr : base_->slot(ref);   // arena_manifold.cpp:30-36
}
```

`linked()`, `contentOf()` and `dimensionsOf()` have the same shape (`:98-135`). **That is federation
with exactly one foreign space**, and it already carries the two properties the general case needs:
reads dispatch on ownership, and writes shadow rather than mutate.

What is missing is only that `base_` is one pointer and that refs carry no space. Generalising it to
a small table is a smaller change than it sounds, and §12 shows the blast radius is two functions.

## 3. Four constraints, and they all push the same way

- **Ephemeral only.** `CompactOpNode`'s `to`, `linkId` and `sourceOpIndex` are `std::uint32_t` in a
  node fixed at 64 bytes by three `static_assert`s. R4 already ruled that a cross-document reference
  cannot live there. So a federated ref exists only in an arena, which is where R8 says a thing with
  no hypertime name belongs.
- **Refs collide across spaces.** Today a base ref is an operation index and an arena ref carries
  `ephemeralBit`, so the two can never be confused. With *two* persistent bases, Alice's operation
  87 and Bob's operation 87 are the same `std::uint32_t`. A space field is not a convenience; it is
  the thing that makes more than one base expressible at all.
- **Refs cannot widen.** `static_assert(sizeof(DimLink) == 12)` and `sizeof(CellSlot) == 32`. Three
  64-bit refs would make a `DimLink` 24 bytes and hand R12's memory argument — 108 bytes per cell
  against the fixed array's 112 — straight back to the design it beat.
- **The bit budget already fits.** A ref is 32 bits, bit 31 is `ephemeralBit`, and the operation
  ceiling is 134,217,727 (`osmic-microversioning-and-dag.md` §5), which is 27 bits. **Four bits are
  free**: one space for the arena's own cells and fifteen foreign, with the index field still able
  to address a maximal store.

## 4. The encoding

```text
bit  31     : ephemeralBit -- set on every federated ref, own or foreign
bits 30..27 : space id; 0 == this arena's own cells, 1..15 == attached manifolds
bits 26..0  : index within that space (dense slot, or the foreign store's op index)
```

**Existing refs do not move.** `refOf(dense)` is `ephemeralBit | dense`
(`arena_manifold.hpp:158-160`), so an arena's own refs land in space 0 and are bit-identical to what
they are today for any arena under 134 M cells. Nothing that holds a ref today needs rewriting.

**`isEphemeral()` keeps meaning exactly what it already means, and that is the load-bearing part.**
A federated foreign cell *is* backed by an operation — in Alice's store — so calling it ephemeral
looks like a lie. It is not: the bit's job is "this ref cannot be persisted as a bare ref in *this*
document", which is precisely why `Store::setLink()` and `applyStructure()` refuse one
(`manifold.cpp:258-261`). A foreign operation index is exactly the reference R4 forbids storing. So
tagging federated refs ephemeral makes every site that tests the bit correct **by construction**
rather than by audit.

```cpp
// beside isEphemeral(), in manifold.hpp
inline constexpr CellRef spaceShift = 27;
inline constexpr CellRef spaceMask  = 0x0F << spaceShift;
inline constexpr CellRef indexMask  = (1U << spaceShift) - 1U;
inline constexpr std::uint8_t ownSpace = 0;
inline constexpr std::uint8_t maxSpaces = 16;

[[nodiscard]] constexpr std::uint8_t spaceOf(CellRef r) noexcept {
  return static_cast<std::uint8_t>((r & spaceMask) >> spaceShift);
}
[[nodiscard]] constexpr CellRef indexOf(CellRef r) noexcept { return r & indexMask; }
[[nodiscard]] constexpr CellRef federated(std::uint8_t space, CellRef index) noexcept {
  return ephemeralBit | (static_cast<CellRef>(space) << spaceShift) | (index & indexMask);
}
```

### 4.1 Three alternatives, and why the tag is in the ref

**Nothing on disk changes, and nothing on disk needs to.** An operation lives in exactly one store's
`ops.nodes`; "which slice is this" is answered by which file it was read from, so a node has no
ambiguity to resolve and gains no field here. Federation is a property of a *reading*, not of a
recording — §3's first constraint arrived at the same place from the node's side.

**`to` is free on three verbs of four, and a table selector in a free field is already §5.6's
design.** Reading the fold rather than the docstring: `MakeCell` takes the span, `value` and
`flags`; `Splice` takes `sourceOpIndex`, `at`, `length` and the span; `SetValue` takes
`sourceOpIndex` and `value`. None of the three touches `to`. **`SetLink` does** —
`const CellRef to = node.to;` (`manifold.cpp:250`) — which `ops.hpp:104` documents as "(this cell,
dimension = `linkId`, direction) -> `to`". So `to` is occupied in exactly the one verb that names
another cell, and `ops.hpp:102`'s "`to` and `linkId` are unused" is `MakeCell`'s own line rather
than a statement about the hyperop.

**Room was never the constraint, and saying so was this section's own error.** A `SetLink` leaves
`at`, `length`, `sourceAt`, `sourceLength`, the sixteen-byte span and the eight-byte `value`
untouched; there is plenty of node to spend. The constraint is R4's and it is *semantic*: a local
spool index is **not swarm-stable** — `opRecords()` emits sorted by `MicroversionId`, so
re-ingesting the same operations lands a branch at a different index — so a foreign reference is a
`GlobalOpRef`, a scroll *key* plus a variable-length hypertime path. That does not inline into fixed
32-bit fields however many are free. **A table index does**, and that is precisely the move
[§5.6](5.6-extern-refs.md) already makes: a placeholder is an ordinary `MakeCell` with
`ValueKind::ExternRef` and the `externals` index in `value`.

**Why `value` rather than `to` carries that index** is worth knowing, because it is the same
argument twice: `applyStructure`'s `MakeCell` case already copies `valueKind` and `value` into the
slot (`manifold.cpp:218-226`), so a manifold answers "what is this a placeholder for" off
`CellSlot::valueBits` with no `Store` in hand. `to` is not copied into the slot, so a selector there
would force a node read on a path documented as `Store`-free.

**None of which supplies the runtime tag, and the reason is the one above.** A placeholder's
`valueBits` *is* a per-cell space selector living in the slot, so for placeholder cells the
home-pointer idea is built already. It does not generalise: a ref in flight has no node and no slot
in hand either, and federation's whole economy is that it does **not** mint a local cell per foreign
cell. The two answer different questions at different rates — a placeholder says once, at fold time,
which document one cell stands for; a space tag says at every hop which manifold a ref indexes.

**A home pointer on the cell is the real alternative, and its rule is the right rule.** "A cell
knows which manifold it came from, and a cell spawned from another inherits it" is correct, and §6's
re-tag is that rule written in bits: `federated(spaceOf(from), answer)` *is* inheritance from the
cell you were spawned from. The disagreement is only about where the tag rides.

It cannot ride in the **slot**, for one reason: a ref is dereferenced with no slot in hand.
`CellRef linked(CellRef from, DimRef, DimVector)` takes and returns a bare `std::uint32_t`
(`manifold.hpp:230`), so finding a cell's slot requires already knowing which manifold to ask. With
one base that resolves itself — try mine, else try theirs. With several, every lookup must try each
in turn, and if Alice and Bob both have a cell at operation 87 the first one tried silently wins.
**The collision happens before any slot exists to consult**, so a pointer inside the slot arrives
too late to prevent it.

It can ride *beside* the ref, as a fat handle — `struct Cell { const Manifold *home; CellRef ref; }`
— and that is a coherent design with real advantages. It needs no encoding change and has no ceiling
on attached spaces. Its cost is the mirror image:

|                                  | tag in the ref's spare bits    | fat handle                                         |
| -------------------------------- | ------------------------------ | -------------------------------------------------- |
| `linked()` and friends           | unchanged                      | signature changes, and every caller with it        |
| `DimLink`, `CellSlot`            | unchanged                      | unchanged either way, since links stay intra-space |
| attached spaces                  | 15                             | unbounded                                          |
| `unordered_map<CellRef, …>` keys | work as they are               | new hash and equality for each                     |
| blast radius                     | one decoder, one encoder (§13) | 89 files mention `CellRef`                         |

**Vortex decides it.** A cell reference enters the VM as
`makeScalarCell(static_cast<std::int64_t>(ref))` (`vortex_stdlib.cpp:1007`) — carried as an integer
scalar, whose canonical bits land in `CompactOpNode::value` under R6 and therefore reach disk
through `promoteAndAttachToStore()`, which the zigzag VQL palette calls in production. A 32-bit
federated ref round-trips that unchanged. A `{Manifold *, CellRef}` cannot: a pointer is not a
scalar, is not stable across runs, and means nothing once promoted. The fat handle would either shut
Vortex out of federated cells or require a new VM value kind, which is a larger change than the one
this note proposes and lands in the language rather than in the arena.

Two smaller differences point the same way. A stale space id fails safe — `spaceAt()` answers
`nullptr` and the read answers `noCell` — where a stale `Manifold *` is a use-after-free with no
guard. And refs are hash keys throughout (`overlay_`, the trail, visited sets, `sourceToDest`),
which bits leave working untouched.

**What the home-pointer framing is right about, and what §6 takes from it:** re-tagging in the bit
design is *manual*, and a missed `federated(space, …)` yields a space-0 ref that silently aliases an
arena cell. Inheritance should therefore be structural rather than remembered — **every read that
delegates to a foreign space goes through one helper that re-tags on the way out, and no read may
call a space's manifold directly.** One choke point is what makes "a cell inherits the space of the
cell it came from" true by construction instead of by discipline. The hazard is named again in §13.

**Also refused: partitioning a flat index range per space** — no bit fields, each attached space
given a contiguous base offset. It founders on the arena's own space growing without bound, so a
contiguous partition needs a fixed cap on space 0 regardless, which is the bit field with a search
in place of a mask.

**The trigger for revisiting**: if a workload genuinely needs more than fifteen attached spaces at
once, the fat handle is the escape hatch, and its price is the VM value kind above. Recorded here so
the choice is re-made rather than rediscovered.

## 5. The API

```cpp
/// One attached manifold, and what it takes to name a cell of it globally.
struct Space {
  const Manifold *manifold{nullptr};
  const xanadu::Store *store{nullptr};   ///< for content reads and op refs
  const xanadu::Scroll *sealedAs{nullptr}; ///< opRefOf() needs it; may be null locally
};

// on ArenaManifold, replacing the single base_
/// Attach @p space, answering its id. Throws above maxSpaces.
std::uint8_t attach(Space space);
[[nodiscard]] const Space *spaceAt(std::uint8_t id) const noexcept;

/// The (store, local ref) a federated ref names, or nothing for an own cell.
[[nodiscard]] std::optional<std::pair<const xanadu::Store *, CellRef>>
resolveForeign(CellRef ref) const noexcept;
```

`ArenaManifold(const Manifold *base)` stays, as sugar for `attach({base, base->store()})` into space
1, so every existing caller compiles unchanged and the COW-over-a-document case remains the thing it
already is.

**A space is attached and never detached.** `ArenaManifold`'s own contract already says a base "must
not be mutated while it is being read through — a shadow copies a cell, not a promise about one";
detaching is that hazard with the pointer removed instead of the bytes changed. Refs into a detached
space would dangle inside shadows, link runs and trail entries with nothing to catch it. Discard the
arena instead, which is what `Mark`/`release` already make cheap for the branch case.

## 6. Reads: decode, delegate, re-tag

```cpp
CellRef ArenaManifold::linked(CellRef from, DimRef dim, DimVector dir) const noexcept {
  if (const auto space = spaceOf(from); ownSpace != space) {
    const auto *const s = spaceAt(space);
    if (nullptr == s) { return noCell; }
    const auto answer = s->manifold->linked(indexOf(from), dimIn(space, dim), dir);
    return noCell == answer ? noCell : federated(space, answer);   // re-tag
  }
  ... // exactly what it does today
}
```

Three things worth stating about this shape:

- **`walkRank` needs no change.** It is a template over `ManifoldT` calling `m.linked(...)`
  (`manifold.hpp:119-157`), so a federated rank walks with the same code a local one does — the same
  property §5.7 prized when it chose a placeholder over a tagged `to` field.
- **A walk inside a space never leaves it.** A persistent cell's links can only name its own store's
  operation indices, because that is all `Store::setLink` can write. So crossings occur only where
  *this arena* wrote a link — an override, a quotation splice, a query result. **The tissue's seams
  are exactly the places somebody authored**, which is the property that makes a federated view
  honest rather than a merge.
- **The hop cost is a shift, a mask, a table index, an indirect call and an `or`.** R12 measured
  4.96 ns sequential and 21.02 ns scattered for a local hop and made its ruling on those numbers, so
  this one owes a measurement before it is believed — see §11 and the vision's §7.

## 7. Bound dimensions become a set, and that is where §5.9 stops being optional

R2 makes a dimension a cell, so Alice's `d.vars` and Bob's `d.vars` are two different cells sharing
a string. Binding `d.vars` across a tissue therefore has to bind a *set*: one dimension cell per
attached space, which is what `dimIn(space, dim)` above is reading.

**The tree already does the name-keyed half.** `DimensionRegistry` is
`(const Store *, internedNameId) -> DimRef` (`dimension_registry.hpp:156`) — one name resolving to a
different `DimRef` per store is exactly what it is for. What it lacks is the notion of a bound set;
callers ask one store at a time.

Two ways to populate the set, and they are not equally sound:

| how                | basis                                                                                 | when it is wrong                                       |
| ------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| by name            | both cells' content reads `d.vars`                                                    | your `d.vars` is not mine, and nothing says so         |
| by shared identity | both quote the same published dimension cell ([§5.9](../structure-hyperop-vision.md)) | it is not wrong; it is an address rather than a string |

`cloneMaster()` following `d.clone` negward is already the tree's "these are the same thing"
mechanism, and R12 already uses it for exactly this — `d.meta-dims` entries are clone cells of the
real dimension cells so that "one dimension needs one identity however many cells link on it."
Federation is that sentence with *documents* in place of cells.

**Ruling: name-binding is allowed and must be visible.** A bound dimension records how each member
was bound, so a reader can tell "these two documents share a dimension" from "these two documents
used the same word." Silently treating a string match as an identity is the error `UserPermascroll`
already refuses to make for content, where "sharing a coordinate is not an optimisation, it is a
claim" (R6). A dimension name is a smaller claim than a quotation, but it is the same kind.

**Consequence for the build order: §5.9 published vocabularies is promoted from "deferred behind 5.8
by dependency, not by weight" to a prerequisite for trustworthy federation.** It is what makes a
cross-document dimension an address.

The resolution costs nothing per hop: `linked()` has already decoded the space in order to dispatch,
so it indexes the bound set with the same field. **The space table and the bound-dimension set are
indexed by the same four bits.**

## 8. Writes: shadowing and promotion

**Shadowing a foreign cell needs one correction to `shadow()`.** It copies the base slot and keeps
`birthOp` deliberately — "the shadow's name is the base cell's ref and not `refOf(dense)`: an
overlaid cell is the *same* cell" (`arena_manifold.cpp:400-401`). Under federation that ref must be
the **federated** one, not the foreign store's raw operation index, or two spaces shadowing their
respective cell 87 produce two slots claiming the same name. The fix is one `federated(space, ...)`
at the copy; the test is in §11.

**`promote()` becomes the persistent image of the tissue, and it is the part that makes this note
pay.** Promotion already "works by *mapping* refs rather than by being trusted with them: every
arena ref is `ephemeralBit`-tagged, so a promotion that forgot to translate one would be refused by
`Store::setLink()`". Under federation it gains a second case:

| the ref names…            | promotes to                                                       |
| ------------------------- | ----------------------------------------------------------------- |
| a cell this arena minted  | a real `MakeCell`, as today                                       |
| a cell of a foreign space | a [§5.6](5.6-extern-refs.md) placeholder naming its `GlobalOpRef` |

That is the whole chain made coherent: **federation is the ephemeral tissue; §5.6's extern reference
is the persistent name of a federated cell; §5.8's quotation is the authored statement that part of
the tissue belongs to your document; and `promote()` is the road between them, which it already
was.** It also gives VQL something it cannot do today — promote a cross-store query answer as real
links, rather than as a copy of somebody else's cells.

## 9. Progressive attachment: the granularity is a space, not a cell

The obvious wish is to load cells lazily as a reader navigates. Half of it is available and half is
not, and the half that is not should be said plainly.

- **Shape is per space.** There is no folding a suffix: `rebuildManifoldFromIndex()` walks the
  ancestral path from the beginning, and a replay missing its prefix is a different document. So
  cells cannot arrive one at a time. What *can* be lazy is **which spaces are attached at all** — do
  not fold Bob's store until navigation crosses into it — and under federation that is cheap,
  because attaching costs a fold rather than a copy.
- **Content is already per cell**, and already lazy: see [§5.8 §6](5.8-quoted-ranks.md), `Scroll`'s
  gaps (`scroll.hpp:263`) and `SwarmContentSource`'s deadline-bounded reads (`swarm.hpp:89-96`).

**Bound dimensions drive both, which is what makes them worth binding.** The bound set crossed with
the view radius (`Manifold::cellsWithinRadius`, and the bridge's configured cell radius) names the
cells whose content to prefetch *and* the crossings that are reachable, hence which spaces are worth
attaching. Switching the bound dimension re-aims both. One signal, two consumers, no new state.

**Filtering the fold itself by bound dimension is refused.** It saves no I/O — every operation on
the path is read in order to walk it — and a dimension-filtered manifold is not `equivalentTo` a
cold fold, which costs `verifyAgainstFullRebuild()` the meaning R9 gave it.

## 10. What it does to the neighbours

- **VQL.** `addStore()` stops copying: it attaches a space, and `d.stores` cells carry federated
  refs. Queries keep identity across stores, so an answer is citable. This is the largest immediate
  win and it is in built code.
- **[§5.8](5.8-quoted-ranks.md).** The materialiser simplifies: attach the space, splice federated
  refs onto the local rank. The import pass and the span-translation step both disappear, because a
  foreign cell's spans stay in the foreign store and the reader dispatches by space. The selector
  survives, but it now bounds **attachment** — what a reader sees as part of this document — rather
  than bounding a copy, so its determinism argument stands unchanged and its memory argument
  softens.
- **[§5.7](5.7-anthology-ranks.md).** An anthology resolves by attaching each member's space. Its
  three per-member states become per-space states, which is fewer of them.
- **§5.10.** This is the composition substrate the overlay mode needs, and it is deliberately *only*
  that: federation says how two manifolds are read together, and says nothing about precedence.
  Which author's structure wins where they disagree, and how a `ProminenceTier` orders them, is
  §5.10's own ruling and is not made here.

## 11. Phasing

1. **The encoding and the dispatch, with one space.** `spaceOf`/`indexOf`/`federated`, the `Space`
   table, and `base_` re-expressed as space 1. Pure refactor: every existing test must pass
   unchanged, and `existingArenaRefsAreUnchanged` proves the bits did not move.
1. **N spaces**: `attach()`, the re-tagging reads, and the `shadow()` correction (§8).
1. **Bound dimension sets** (§7), with binding provenance recorded.
1. **`promote()` to placeholders** (§8), which needs [§5.6](5.6-extern-refs.md) phase 1.
1. **VQL stops copying** (§10) — the first production consumer, and the one with existing tests to
   hold it honest.
1. **Progressive attachment** (§9), driven by the bound set and the view radius.

Phases 1–3 are self-contained and need no other section of the vision.

## 12. Tests

- **`twoStoresWithTheSameOperationIndexDoNotCollide`** — the reason the space field exists: attach
  two stores, each with a cell at operation 87, and assert the two federated refs differ and resolve
  to different cells. Impossible to express today, which is why it is first.
- **`existingArenaRefsAreUnchanged`** — space 0 compatibility: `refOf(n)` is bit-identical before
  and after phase 1. What makes phase 1 a refactor rather than a migration.
- **`aFederatedHopAnswersTheForeignCell`** — `linked()` across a space boundary, re-tagged.
- **`aWalkInsideASpaceNeverLeavesIt`** — §6's seam property: walk a foreign rank of ten and assert
  every ref carries the same space.
- **`aFederatedRefKeepsItsIdentity`** — recover a `GlobalOpRef` from a federated ref and assert it
  names the foreign cell. **This fails today under `importManifold` and is the defect in §1.**
- **`aShadowOfAForeignCellKeepsItsSpace`** — §8's correction: shadow cell 87 in two spaces and
  assert two slots with two names.
- **`promotingAForeignCellMintsAPlaceholder`** — §8's table, and the join to §5.6.
- **`aBoundDimensionResolvesPerSpace`** — bind `d.vars` across two stores and assert each hop uses
  that space's own dimension cell.
- **`aBoundDimensionRecordsHowItWasBound`** — §7's ruling: a name-bound member is distinguishable
  from an identity-bound one.
- **`vqlAcrossTwoStoresCopiesNothing`** — phase 5: assert the arena's own cell count is unchanged by
  attaching two documents. The whole point of the note, as one number.
- **`theFederatedHopCostIsMeasured`** — a benchmark, not an assertion, against R12's 4.96 ns
  sequential and 21.02 ns scattered. R12 named the traversal size at which its own ruling should be
  revisited; this one should arrive with the same courtesy.

## 13. Risk

**The encoding is the whole risk, and it is far smaller than it looks.** Seventeen files mention
`ephemeralBit` or `isEphemeral`, but the encoding is decoded in exactly **one** place —
`ref & ~ephemeralBit` at `arena_manifold.cpp:22`, inside `denseOf()` — and constructed in exactly
one, `refOf()` (`arena_manifold.hpp:158`). Every other site only *tests* the bit, and §4 is why
those stay correct. A grep for `~ephemeralBit` is the complete audit, and it should stay a
one-result grep afterwards: a second raw decode is how a space field goes silently missing.

**A missed re-tag is the silent failure**, and §4.1 is why it is a structural rule rather than a
warning: a foreign answer returned without `federated(space, …)` is a space-0 ref that aliases an
arena cell, with no type error and no assertion. All foreign delegation goes through one helper; a
second call site that reaches a space's manifold directly is the defect, and is worth a grep in
review.

**The enumeration hazard is real and is not caught by types.** `cellCount()` and `cells()` mean
"this arena's own", so a loop of the shape at `vortex_stdlib.cpp:966-969` —
`for (c = 1; c < cellCount(); ++c) refOf(c)` — enumerates space 0 and silently skips every attached
space. Today that is correct, because space 0 is everything. Under federation, every such loop needs
to say whether it means "mine" or "all", and there are five of them in `vortex_stdlib.cpp` alone.
This is the same observation [§5.8 §8](5.8-quoted-ranks.md) makes about consumers written against
`Manifold::cells()`, arriving from the other direction.

**Fifteen spaces is a ceiling**, and a deliberate one. If a workload wants more, the answer is a
per-view federation rather than a wider ref, because widening costs R12 its memory argument (§3).
Fifteen is comfortable for a reading view and for an anthology; it is not obviously enough for a VQL
query over an unbounded corpus, and that is the falsifiable point at which this ruling wants
revisiting — stated here in R12's own style so the trigger is recorded rather than discovered.

**The hop regression** is the other measurable. One extra branch on the common path (space 0) is the
best case; the foreign path adds an indirect call that will not inline. If the local hop regresses
at all, space 0 should be split out before the decode rather than after.
