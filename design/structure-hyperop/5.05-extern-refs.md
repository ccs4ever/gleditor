# 5.5 — Persistent references to cells in other stores

Implementation plan for §5.5 of [`structure-hyperop-vision.md`](../structure-hyperop-vision.md).
**Status:** ready to implement in its final rank-backed shape. **Depends on:** §5.4 for scroll cells
and replay indexes, and shares §5.2's `ValueKind` mechanism. **Provides:** the persistent boundary
cell used by §5.8–§5.12 and the address semantics §5.6 must carry on the wire.

This is the load-bearing section: every remaining proposal needs a cell in one document to name a
cell in another, and nothing in the tree can do that today.

## 1. R4 already ratified the address

`store-slice-convergence.md` R4 specifies `GlobalOpRef{scroll, produces}` and the
`opRefOf()`/`localiseOpRef()` pair. The global scroll key survives publication and the
`MicroversionId` survives branch-driven index renumbering; a bare foreign `CellRef` survives
neither. What R4 did not settle was where that variable-length pair lives persistently.

§5.4 settles it without a side table. The global scroll identity already has a cell on `d.scrolls`.
The operation name belongs to the placeholder itself. The local API may still use the convenient
pair:

```cpp
struct ExternOpRef {
  ScrollId scroll{localScroll};
  MicroversionId produces;
};

struct GlobalDocumentState {
  std::string scroll;
  MicroversionId version;

  bool operator==(const GlobalDocumentState &) const = default;
};
```

`ExternOpRef` names one operation through a store-local scroll id. `GlobalDocumentState` names a
whole document snapshot through its global scroll key, without pretending that some arbitrarily last
operation is the document. The latter is shared by §5.8 pouch provenance and §5.12 overlay targets.
`writeGlobalDocumentState()` and `readGlobalDocumentState()` provide one versioned, length-prefixed
codec for both consumers. Its bytes are ordinary descriptor content, not a wire record or a row
stored outside hypertime.

## 2. The persistent shape

```text
home ──d.scrolls──> [ scroll S: global key ]
                       │
                       └──d.scroll-refs──> [ P1: "1a2", ExternRef ] ──> [ P2: "7" ]
```

A placeholder is an ordinary `MakeCell` with `ValueKind::ExternRef = 5`, `value == 0`, and the
canonical `MicroversionId::str()` of `produces` as its content. It is appended to the
`d.scroll-refs` rank anchored at the scroll cell. `MicroversionId::parse()` is the inverse.

Three details are load-bearing:

- **`produces` cannot live in `value`.** A `MicroversionId` is variable length and already contains
  a vector; squeezing it into 64 bits would recreate the local-index bug under another name.
- **The membership rank is not `d.scrolls`.** A ZigZag cell has only one neighbour per direction on
  a dimension. The registry rank already consumes the scroll cell's `d.scrolls` slots, and many
  placeholders cannot all point directly at it. `d.scroll-refs` is one rank per scroll, with the
  scroll cell as its head.
- **The descriptor bytes are ordinary primedia.** Resolving a foreign reference may fetch the few
  bytes spelling its operation name. It does not fetch the foreign cell's content. This is the
  honest price of removing the side table while keeping the 64-byte node fixed.

One replay index maps `(ScrollId, MicroversionId)` to the unique placeholder and maps a placeholder
back to its pair. It is rebuilt from `d.scrolls`, `d.scroll-refs`, and descriptor content; it is not
a sixth mutable table. Filing the same global reference twice reuses the same cell.

## 3. Node, fold and wire

**Node.** No layout change. A reference to a foreign cell is an ordinary `SetLink` whose `to` is the
placeholder. No `SetExternLink` verb is needed: the link is local; only its target stands for
something remote.

**Fold.** `MakeCell` already copies `valueKind` into `CellSlot`. `Manifold` records every
`ExternRef` cell in `externalCells` and counts unresolved placeholders separately from
`refusedOps()`. It does not parse content or resolve a store: `applyStructure()` remains
allocation-free and `noexcept`.

**Wire.** §5.6 needs no ExternRef-specific payload. The descriptor travels as the placeholder's
ordinary span, and the scroll association travels as ordinary Structure links. V4's responsibility
is more general and stricter: every address-bearing Structure field (`source`, a `SetLink`'s
dimension and target, and an `OpHandle` target) travels by `MicroversionId`, never by a publisher's
local index. That makes the entire graph containing the placeholder survive ingestion.

**Merkle cost.** The node remains 64 bytes and piece alignment is unchanged. Each distinct foreign
reference appends only its short operation-name text to the author's permascroll plus the ordinary
placeholder and rank-link operations.

## 4. Authoring and lookup

```cpp
MicroversionId makeExternRef(const MicroversionId &parent,
                             const ExternOpRef &target);

[[nodiscard]] std::optional<ExternOpRef>
externTarget(zigzag::CellRef placeholder, const SpanReader &reader) const;
```

`makeExternRef()` requires the scroll to have a `d.scrolls` cell, consults the replay index for an
existing pair, otherwise mints P and appends it to S's `d.scroll-refs` rank. `externTarget()` is a
resolver-side call: it obtains S's derived `ScrollId` from the membership index and parses P's
content. A malformed descriptor is `Unintelligible`; an unavailable descriptor span is `NotFetched`,
not corruption in the manifold.

**That distinction is the Nelsonian heart of this section.** A link to a document you do not have
yet is normal in a docuverse. Conflating “not here yet” with “this spool is corrupt” would make the
docuverse's ordinary state an error state.

## 5. The real cost: resolution is not a lookup

This is where the vision's "resolution on demand, memoised in an arena" hides the actual
engineering, and it should be stated plainly before anyone estimates this section.

To turn a placeholder into a foreign cell you must:

1. find the foreign store — the registry gives you a `Scroll`, i.e. a publisher key, a salt and
   segment locations, **not an open store**;
1. load it, which may mean fetching over BitTorrent;
1. know its `sealedAs` scroll, because `localiseOpRef()` refuses a ref that names another document
   and every history numbers its first state "1";
1. call `localiseOpRef(foreignStore, ref, sealedAs)` for an index — which is `const` and records
   nothing, by explicit design; and
1. **fold a `Manifold` on it**, because an index is not a cell.

So resolving one extern ref costs a document load and a fold. That implies a foreign-store cache
keyed by scroll, with a lifetime policy, which nothing in the tree has — `MultiStoreCoordinator`
composes stores the caller already opened.

**Three states, not two.** `Scroll::segments` "may have gaps: a stretch nobody has sealed yet is
simply not here, and reads as missing rather than as something else." So a placeholder is
*resolved*, *not fetched yet*, or *permanently absent*, and the UI needs to tell the second from the
third — a spinner is not a dead link. `unresolvedExternals()` counts the latter two; distinguishing
them is a resolver concern, not a fold concern.

**The fold never resolves.** `applyStructure` is `noexcept` and allocation-free, and resolution is
I/O. The fold mints placeholders and counts them; a resolver above it fills them in. Keeping that
line sharp is what stops a network fetch appearing inside a manifold rebuild.

## 6. Phasing

The first two phases are self-contained and testable with no network and no second document on disk.

1. **`ValueKind::ExternRef`, `d.scroll-refs`, placeholder minting, and the replay index**, plus
   `externalCells` and `unresolvedExternals()`. A store can record and reload a reference; it
   resolves nothing.
1. **`makeExternRef()`/`externTarget()` and the existing globalise/localise pair**, including
   interning by `(ScrollId, MicroversionId)`.
1. **§5.6's stable Structure-address wire**, completing publication for the graph this step writes.
1. **The resolver** (§5): a foreign-store cache, the three-state answer, and memoised resolution.
   The largest piece by far, and the one that should be scoped on its own once phases 1–2 exist.
1. **Consumers**: §5.9 anthology ranks, §5.10 quoted structure, and the refiled
   [§5.8](5.08-pouch-items.md) pouch model.

## 7. Tests

- **`anExternPlaceholderSurvivesAReload`** — record a reference to a foreign cell, save, load, and
  assert the placeholder is still a cell, still `ExternRef`, and still names the same
  `{scroll, produces}`. The core of phase 1.
- **`anUnresolvableExternIsNotCorruption`** — fold a store whose extern names a scroll the registry
  has no bytes for; assert `refusedOps() == 0` and `unresolvedExternals() == 1`. The distinction
  this section exists to draw, as an assertion.
- **`aRankDeadEndsAtAPlaceholderRatherThanVanishing`** — walk a rank through an unresolved extern
  and assert the placeholder and its operation-name descriptor remain visible.
- **`aPlaceholderIsNotEphemeral`** — `Store::setLink` accepts it where it refuses an `ephemeralBit`
  ref. Guards R8's boundary against being widened by accident.
- **`anExternRefSurvivesTheForeignStoreGainingABranch`** — the R4 regression and the reason none of
  this can be a bare index: seal a foreign store, reference a cell, add a branch to the foreign
  store so its indices renumber, and assert the reference still resolves to the same cell.
- **`anExternRefIsRefusedForTheWrongDocument`** — `localiseOpRef`'s "every history numbers its first
  state 1" guard, exercised through this path.
- **`twoReferencesToOneForeignStoreShareAScrollCell`** — both appear on one `d.scroll-refs` rank,
  while two references to the same operation reuse one placeholder.
- **`manyPlaceholdersDoNotDisplaceTheScrollRegistryRank`** — the degree-two regression that rules
  out linking every placeholder directly on `d.scrolls`.

## 8. Risk

**Phase 1 is additive and bounded**: no node change and one `ValueKind`, but it does add a replay
index and descriptor parsing. Its central risk is still the distinction in §4: unavailable bytes
must not increment `refusedOps()`.

**Phase 4 is the large and genuinely uncertain one.** A foreign-store cache with a lifetime policy,
fetch-in-progress states, and folds of documents the user did not open is a subsystem, not a
function. It should not be estimated together with phases 1–2, and nothing in §5.9–§5.12 needs it to
*record* references — only to *display* them resolved.

**There is no second table migration.** §5.4 has already regenerated the fixtures around the final
rank-backed registry; this step adds ordinary operations and content only.

```sh
make -j$(nproc) test TEST_FILTER='*Extern*:*StoreTables*:*Manifold*:*Publication*'
make -j$(nproc) test && make format-check && make lint
```
