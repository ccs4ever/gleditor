# 5.1 — `d.hist`: surfacing a cell's own past

Implementation plan for §5.1 of [`structure-hyperop-vision.md`](../structure-hyperop-vision.md).
**Status:** ready to implement. **Depends on nothing. Provides:** the history API used by §5.2's
handle tests and §5.3's edition history. **Appends no operations, changes no format, invalidates no
fixture, and writes nothing.**

The cheapest item on the list: every byte it needs is already stored and already verified. What is
missing is a way to ask.

## 1. What is already there

R7 gives every cell a backward chain of the operations that shaped it, and the fold already
maintains both of its ends:

- **`CellSlot::birthOp`** (`manifold.hpp:195`) is the `MakeCell` index, which *is* the `CellRef`.
- **`CellSlot::lastOp`** (`:196`) is the head of the chain, written by all four verbs
  (`manifold.cpp:220`, `:300`, `:313`, `:334`) and **compared by `verifyAgainstFullRebuild()`**
  (`:529`) — so its correctness is under test today, which removes the usual first risk.
- **`CompactOpNode::sourceOpIndex`** is each operation's link to the previous one on the same cell.
- **`SegmentedOpsSpool::get(index)`** (`segmented_ops_spool.hpp:260`), reached through
  `Store::get(index)` (`store.hpp:156`), turns an index into a node.

`Store::lastOpOnCell()` (`store.hpp:901`, `store.cpp:298-315`) already assembles exactly these
pieces for the writer's benefit, and its doc comment records the two facts this plan is built on:
**a chain link always names a lower index than the operation holding it**, so a backward walk
strictly decreases and one pass settles it; and **the answer is per-branch** — "the last operation
on a cell is a different operation on two futures of the same state."

That second fact is the whole subtlety of this section, and §3 turns it into an API constraint.

## 2. Three corrections to the draft

The vision note sketched this as "`byRef` already holds the chain; return a `span<const CellRef>`".
Reading the code says otherwise, and the shape of the work changes.

- **`byRef` does not hold the chain.** It is `std::unordered_map<CellRef, std::uint32_t>` mapping
  *operation index to dense slot* (`manifold.hpp:256-258`). It answers "which cell does this
  operation belong to" — which is what `denseOf(node.sourceOpIndex)` needs at `manifold.cpp:248` —
  and not "what is this cell's chain". It is many-to-one and unordered. You could recover a chain by
  scanning the whole map for entries pointing at one dense slot and sorting the keys, but that is
  O(all operations) for a question the nodes answer in O(chain).
- **Nothing can return a `span`.** No array of a cell's chain is stored anywhere; a span would have
  to point into something this call allocated. `historyOf()` therefore materialises a vector. The
  histories in view are short, its callers need stable chronological order, and keeping the Store
  access in `manifold.cpp` avoids putting a Store-dependent template in a header that only forward
  declares `Store`.
- **The walk needs the associated `Store`, and `Manifold` already has it.** `Manifold::store_` is a
  non-owning `Store *`; `Store::rebuildManifold*()` calls `setStore(this)`, `advance()` refreshes
  it, and `dimensionNamed()` already uses it. The class header's "no Store access" promise describes
  the allocation-free fast read-path group, not every method on the class. History belongs in the
  smaller store-backed query group beside `dimensionNamed()`, with the distinction documented.

And one addition the draft did not separate: **enumerating the chain is not reconstructing a past
state.** See §4.

## 3. The API

One public call; the loop that follows predecessor links stays an implementation detail.

```cpp
// Manifold, in a store-backed query section after the fast read path.
//
// Every operation that shaped `cell` in this folded state, chronological
// (oldest first), so it reads the way a history is spoken about. Empty for an
// unattached manifold, an absent cell, or a malformed chain.
[[nodiscard]] std::vector<std::uint32_t> historyOf(CellRef cell) const;
```

Putting the API on `Manifold` removes the dangerous part of the earlier signature: there is no
separate `parent` plus optional `known` manifold that a caller can accidentally take from different
branches. **A cell's history is branch-relative, and the manifold already is the selected branch.**
Its `slot(cell)->lastOp` is the O(1) head for exactly that state; the associated store is needed
only to dereference nodes while following their predecessor links.

The implementation is a short reverse walk: reject a null `store_` or absent cell, start at
`slot(cell)->lastOp`, append indices while following `sourceOpIndex`, stop at the `MakeCell` whose
index is `cell`, then reverse the result. Reaching `0` before that birth is a malformed chain and
returns empty. Because indices strictly decrease, termination needs no cycle set; cap the walk at
`foldedThrough() + 1` steps so a corrupt spool cannot monopolise a caller.

**Why the association remains a raw pointer rather than `std::weak_ptr`.** A weak pointer needs a
`shared_ptr` control block, while stores throughout the tree are stack objects or owned by
`unique_ptr`; changing that ownership model merely to make one query compile would be a broad and
unrelated migration. The existing `Store *` already expresses the intended non-owning association.
This plan documents the lifetime contract explicitly: an attached manifold must not outlive its
store. If the project later wants checked lifetime rather than that contract, it needs one coherent
store-ownership change, not a history-specific weak pointer.

## 4. Past states are a replay, not a lookup

"Quote the third draft of this paragraph" needs the cell's *content* at an operation, which the
chain does not directly hold:

| verb       | effect on content                       |
| ---------- | --------------------------------------- |
| `MakeCell` | sets the whole content                  |
| `SetValue` | replaces the whole content              |
| `Splice`   | edits `[at, at + length)` — a **delta** |
| `SetLink`  | none                                    |

So a state is a fold of the chain from `birthOp` forward, and `Splice` is the only reason it cannot
be read off a single node. Two consequences:

- For a cell no one has spliced — which is most cells, and every cell in a freshly projected slice —
  the content at operation *N* is simply the span on the most recent content-bearing operation at or
  before *N*. Worth a fast path, because it makes the common case a lookup after all.
- Otherwise: collect the chain (§3), reverse it, and replay content only. This is `setContent`/
  `spliceContent` logic (`manifold.cpp:232-239`) over a local `std::vector<PrimediaSpan>` rather
  than over the arenas, and it is a few dozen lines.

```cpp
// Content of `cell` as of `op`, which must be in its chain. Empty if not.
[[nodiscard]] std::vector<xanadu::PrimediaSpan>
contentAsOf(CellRef cell, std::uint32_t op) const;
```

Rendering it to text is then the caller's existing `SpanReader`, exactly as `Manifold::textOf()`
does — no new reading machinery, and transclusion keeps working because a past state is addressed by
the same permascroll spans the present one is.

## 5. Phasing

Ship in this order; each phase is independently useful and independently testable.

1. **`Manifold::historyOf`** (§3). Unblocks "which operations touched this cell, and in what order".
1. **`contentAsOf`** (§4). Unblocks "what did it say then", with the no-splice fast path.
1. **The `d.hist` rank, in an arena** — *optional, and deferred until a caller asks.* Minting one
   ephemeral cell per historical state on an ephemeral `d.hist` dimension makes a cell's past
   *navigable* in zigzag rather than merely queryable, and an `ArenaManifold` is the right home
   because none of it is authorship (R8). Nothing in the tree needs this yet: `xudu`'s hypertime
   view is whole-document, and the zigzag visualizer has no per-cell history affordance. Building it
   before a caller exists would be a rank maintained against a hypothesis.

Phases 1 and 2 are the plan. Phase 3 is recorded so that the *name* `d.hist` has a defined meaning
when someone reaches for it.

## 6. Tests

All in `tests/xudu/manifold_test.cpp`, beside the existing chain coverage.

- **`aCellsHistoryIsEveryOperationThatShapedIt`** — mint a cell, `setCellText`, `setLink`,
  `setValue`; assert `manifold.historyOf()` returns exactly those four indices, oldest first,
  beginning with the `MakeCell` whose index is the `CellRef`.
- **`aCellsHistoryIsPerBranch`** — the one that matters, and the one a naive implementation fails.
  Branch a state, edit the same cell differently on each future, and assert the two histories share
  their prefix and diverge after it. This is `lastOpOnCell`'s "different operation on two futures"
  turned into an assertion.
- **`anUnattachedManifoldHasNoHistory`** — a default manifold answers empty rather than
  dereferencing a missing store. This is the explicit boundary of the non-owning association.
- **`aCellNobodyTouchedHasAHistoryOfOne`** — a bare `MakeCell`; the chain is just itself.
- **`contentAsOfReplaysASplice`** — a cell spliced twice; assert the content at each operation, and
  that the final one equals `Manifold::contentOf()`. The fast path and the replay path must agree
  where they overlap.
- **`contentAsOfRefusesAnOperationFromAnotherCell`** — passing an index not in the chain answers
  empty rather than something plausible.

## 7. Risk and blast radius

**Additive only.** No existing signature changes, no stored layout moves, nothing is written to
disk, and `refusedOps()` is untouched. The one shared thing the plan leans on — `CellSlot::lastOp` —
is already maintained by all four verbs and already compared by `verifyAgainstFullRebuild()`, so if
it were wrong the manifold suite would be red today.

**The one real semantic risk is branch-correctness**, and `aCellsHistoryIsPerBranch` makes it loud.
Keeping the query on the manifold is the mitigation: the history head is the `lastOp` belonging to
the already-folded branch, with no second branch parameter that can disagree with it. The lifetime
risk is pre-existing in `store_`; documenting it and testing the unattached case keeps this feature
from making that contract less explicit.

```sh
make -j$(nproc) test TEST_FILTER='*History*:*Manifold*'
make -j$(nproc) test
make format-check && make lint
```
