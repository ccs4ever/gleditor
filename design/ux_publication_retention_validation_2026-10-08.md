# Offline publication quotation retention — 2026-10-08

## Result and scope

Commentary quotations and private pouch cards now retain their immutable carrier files when saved
through Xuzz. A local worker verifies complete carriers, stages copies, verifies the staged bytes,
and installs each carrier under the destination store's `published/<hash>` directory. Native draft
saving completes independently; notifications distinguish preparation, offline readiness and
failure. The existing Save action retries retention after the source publication has been reopened.
Completion bursts are consolidated into one readiness notice per frame. Failure notices retain the
draft and ask the reader to check local storage, reopen the source and save again.

This repairs the missing-carrier restart failure recorded in
[the commentary validation](ux_publication_commentary_validation_2026-10-08.md). It does not certify
all P1–P7 publication journeys or replace the mock identity verification step.

## Persistence and ownership

The shared engine retention helper also serves publication installation. Requests own copied foreign
scroll descriptors, local seed paths and mounted metainfo. They borrow no Store, Resolver or network
source. Every registered foreign segment is checked, including history and link-only references.
Author operations, edition choices and source permascroll bytes are unchanged.

One worker coalesces pending requests per destination and suppresses superseded results. Normal
shutdown flushes edits and drains retention before temporary source directories disappear. Reopening
queues a full carrier review on the worker; opening registers matching metainfo, while the Resolver
verifies individual pieces when used. Full carrier hashing is not added to the UI opening path.

Existing valid copies are verified and reused. Corrupt existing copies and pre-existing staging
folders are refused and preserved. Source escapes, destination symlinks (including ancestors before
`..` traversal), invalid file coordinates and incomplete carriers are refused. Copies are staged and
verified before rename; a failed request does not claim readiness.

## Checks

The expanded reader journey passed on OpenGL, OpenGL ES and Vulkan. The final build passed. The
complete engine run passed 1,315 cases, with 17 expected skips: 16 namespace-only cases run
separately and one unavailable video case. All 12 retention cases, including the native
sidecar-collision reload, passed. Xuzz passed all 61 cases and the slice/overlay suite passed all
193 cases. Namespace transport passed 12 cases and publication integration passed all four cases
earlier in this batch, before the final mounted-layout and notification refinements.

Format-check, lint, the UI text-policy check and `git diff --check` passed. The initial focused run
passed the offline journey and 29 other cases but failed one test setup: an earlier refusal had
created an empty destination before the test tried replacing it with a symlink. The setup now
removes that directory explicitly. The initial broad engine run narrowly failed the unrelated
memoization speed assertion (34,971 hits/s against a 35,000 threshold); its isolated retry passed at
35,371 hits/s, and the final complete run passed. Earlier logs remain alongside the successful final
run; no assertion or verification requirement was weakened.

The broader engine run exposed two orchestration failures because `--torrent` files were accepted
but not registered. Batch orchestration now registers those sources before resolving spans. The
three-document fixture also omitted the second file named in its torrent; that payload is now
written, rather than relaxing whole-carrier verification. The retention helper accepts mounted
single-file and flat multi-file payload roots as well as the immutable seed layout. Multi-file
payloads named `metainfo.torrent` retain their nested payload separately from the metadata sidecar.
A single-file payload with that reserved filename is refused explicitly because the current seed
layout cannot hold both at the same path.

The carrier regression records one 70,013-byte multi-file copy on a cold save and zero copied seeds
on reuse after source removal. This checks copy counts and cross-64-KiB addressing, not latency or
throughput. No responsiveness or large-file performance claim is made.

## Remaining work

Pending retention requests are not durable across abrupt process termination or power loss. A
pre-existing `.partial` directory is preserved and refused rather than silently removed. Normal
shutdown and successful offline-ready completion are the durability boundary validated here.

Pointer document-drop translation, pouch origin navigation, F9's startup-store assumptions,
populated bench presentation and provenance labels remain from the preceding report. Bob and Carl's
full commentary publication, backlinks, Alice's reply and update notifications still require P4/P5
reader validation, followed by the complete P1–P7 acceptance run.
