# Luna 1 native validation report

Run against the linked native `xuzz` build on `feat/spatial-ui-overhaul`; no product files were
edited. Every run used `/workspace/spatial-build/run.sh`, which supplied a fresh offscreen SDL and
XDG profile. Frames were inspected. The build reports `accessibility: not in this build`; saved
trees are diagnostic output, not an AT-SPI session.

The native reading-place subset passes: I authored a real Link through document selections and the
UI bench/forge chords, selected Left member 1 and an occurrence, entered it with `Alt+Shift+Return`,
and returned with `Alt+Shift+O`. The same selected passage remains readable in the quiet, expanded
and refolded captures. The expanded tablet reports Link 21, Left 1/2 place 1/1, three right members,
current state `a34` at bytes 0–20, return checkpoint `a34` at bytes 0–20, and reader visit 1. The
selected source range is the same document as the origin, so Enter does not establish distant-cell
travel.

A separate paired run establishes the write boundary for selection/inspection/folding. Its saved
source operation dump is byte-for-byte identical before and after selecting the Link and
expanding/folding the tablet (36 lines in each). The activity operation dump grows from 75 to 120
lines because it appends session place/checkpoint and selection metadata, but `d.activity-visits`
remains unchanged: both dumps contain only the initial `visit2 0` record, with no completed visit
added by selection, inspect or fold. See `evidence/luna-1/no-write/comparison.json` and its
before/after dumps.
