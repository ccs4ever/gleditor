# Luna validator 2: native J17–J21

Validated the native xuzz UI built from the shared `e9726a6b` baseline plus the first uncommitted
increment. All product source remained untouched by this validation. Screenshots were captured from
the graphical app and converted to PNG without changing the stored PPM originals. The per-step
outcomes are also in [luna-2-results.json](luna-2-results.json).

The assigned concepts are mostly dependency-gated in this build. The existing publication telescope
and hypertime comparison tab are real controls, but their presence does not validate the imagined
acquisition and cross-media search flows. Here, **No affordance** means the needed control or action
was not exposed in the inspected native UI; **Missing** means the required publication, branch,
result or state fixture was unavailable. These observations describe this UI and isolated profile
only. They do not establish that an acquisition or search backend/architecture is absent. I did not
infer behavior from concept mockups, and none of J17–J21 was completed end to end.

The native helper reports `accessibility: not in this build`; therefore no AT-SPI session was run.
The retained accessibility dumps are diagnostic trees only. The `tools/ux-journey.py` results are
stage replay results, not independent journey passes. Its J3 reuse stage exited nonzero because the
stale requested label did not match the displayed action. The baseline run used
`/workspace/spatial-build/run.sh` with `/workspace/spatial-build/baseline-bin/xuzz` and a separate
data/config/cache profile; it only verifies that the retained source store did not recreate the same
pouch row.

Profiles were isolated under `luna-2-profiles/` during the run and archived outside Git afterward;
`evidence/luna-2/profile-manifest.json` records their identities. Review artifacts remain under
`evidence/luna-2/`. I did not run `make`, tests or build commands.
