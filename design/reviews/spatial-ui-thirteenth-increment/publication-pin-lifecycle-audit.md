## UX check: Walks current versus selected visit

The previous Walks form used one `selected` ID both to choose the row and append “Selected visit N”
to the notice (`apps/common/ui/walks.cpp`). It could not distinguish current focus from a previewed
older branch. The current candidate diff passes `linkContext.currentVisit()` separately from
`walksState->first`, prepends `Current visit N` or `No current visit`, and marks the matching option
and accessible description as current. The selected row and notice remain independent. This is the
right small treatment: it adds no action or setting, and the new form regression checks that preview
leaves current unchanged and a later current visit updates the marker. Native Walks frames for this
candidate are still unreviewed.

## D2 gate

Do not begin D2 history enumeration on the strength of package fixtures or signed manifests alone.
The existing package acquisition and signing layers provide useful immutable identities and
integrity gates, but reader curation currently couples enabling with retention, has no independent
emphasis preference, and dismisses selected context when disabling a package. Before D2 consumes
reader-visible package history, verify (through actual controls and restart) that the selected
carrier remains pinned while disabled, that its enabled/emphasis/retained states are separately
reported, and that unknown identity, invalid signature/payload, and unavailable referenced content
remain distinct. No network simulation is evidence of native trust or acquisition behavior.
